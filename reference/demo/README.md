# Vibe Zoo Live Demo

평가자가 설치·로그인·키·서버 없이 체험하는 독립 정적 웹앱입니다. 실제 Backend·Bedrock·MCP를 호출하지 않습니다. Discover, 시험 실행, 채팅, Record와 개인 Skill은 브라우저 메모리의 합성 상태로 연결됩니다. 실제 Extension 증거는 `evidence.html`에서 구분해 제공합니다.

로컬: `python3 -m http.server 18762 --directory reference/demo` 후 localhost:18762에 접속합니다.

체험 선택 순서는 **메일 → WaferSight → MinIO**입니다. 메일은 Gmail에 익숙한 사용자를 위한 독립 합성 화면입니다. Discover → 구성 확인 → `회의` 시험 검색 → 채팅으로 `견적` 검색 → Record 중 `출장` 검색 → 종료 후 설명 보완 → Skill 생성 → `일정`으로 재사용하면 입력과 결과가 연결되는 흐름을 가장 쉽게 볼 수 있습니다. 실제 메일을 연결하거나 발송하지 않습니다.

MinIO 권장 순서: Discover → 도구 구성 보기 → 새 이름으로 시험 실행 → 채팅으로 다른 버킷 생성 → Record 시작 → 웹앱의 Create Bucket에서 직접 생성 → Record 종료 → 의도 입력 → 개인 Skill 생성 → 다른 이름으로 재사용. 추가 체험은 버킷별 모니터링과 Access Key 발급·명시적 삭제입니다.

고정 Guide Tour 대신 단계 번호가 있는 말풍선 welcome card가 실제 버튼·입력 폼 옆에 표시됩니다. 노란 강조는 유지하며 패널 접기·펼치기에도 대화 초안과 진행 상태를 보존합니다. 이전 단계는 해당 시점의 합성 상태를 복원하며, 안내 건너뛰기·자유 탐색·가이드 재개·처음부터 다시 체험을 지원합니다. 초기화는 Live Demo의 메모리만 지웁니다. 실제 자산·데이터에 접근하지 않습니다.

WaferSight 권장 순서: Discover → 구성 보기 → DEMO-A / ETCH-01 시험 → 채팅으로 DEMO-B / ETCH-02 조회 → Record → 웹앱에서 제품 변경 → 종료·의도 입력 → Skill 생성 → DEMO-C 등 다른 조건으로 재사용. 추가로 I-MR/부분군 평균 표현과 웨이퍼맵을 탐색할 수 있습니다. 표본·Cpk는 합성 데이터에서 계산하며 관리도 전체 기능을 재현하지 않습니다.

반도체 체험은 실제 제공된 WaferSight의 대시보드, 파라미터·제품·설비 선택, 관리도와 OOC/OOS 알람을 참고합니다. 모든 수치·제품·설비 데이터는 독립 합성 데이터이며 실측이 아닙니다.

GitHub Actions **Deploy guided experience**를 수동 실행하면 `reference/demo`만 Pages에 배포합니다. 워크플로우에서 기존 공개 스크린샷을 배포용 `evidence/`에 복사합니다. `.env`, `.local`, Backend와 계정은 포함하지 않습니다. 영상은 아직 공개 파일·링크가 없습니다.

실제 Extension의 새 사이트 모델 전송 범위, 참여자별 계정 구분, 다중 도구 Discover 확장은 후속 작업으로 남아 있습니다. Live Demo의 기능 범위를 실제 Extension 검증 완료로 해석하지 않습니다.

## 공개 배포 검증

2026-09-09, 공개 주소 https://hjsg1010.github.io/vibe-zoo/ 를 Orca 내장 브라우저에서 직접 열어 두 체험의 최초 진입, 도구 시험 입력, 채팅 결과 변화, Record·의도·다른 입력의 Skill 실행, 자유 탐색, 초기화를 확인했습니다(14개 확인 항목). 테스트는 DOM의 실제 버튼 클릭·폼 제출·선택 변경을 사용했고 상태 객체를 주입하지 않았습니다. 838px 너비 화면을 육안 확인했으며 가이드와 시험 폼의 위치가 겹치지 않고 조작 영역이 뷰포트 안에 있음을 확인했습니다. 실제 Extension 스크린샷 4개와 증거 페이지의 공개 응답도 확인했습니다. 이는 Live Demo 검증이며 실제 모델·브라우저 자동화 성공으로 계산하지 않습니다.

Discover는 4단계 진행 막대를 보여주고, 완료 후 시험 실행 전에도 대화를 열어둡니다. 웹앱 실행은 후보 시험 뒤에 가능하며 Record 종료 시 녹화한 버킷 이름 또는 조회 조건으로 설명 초안을 채웁니다. 사용자는 필요한 목적·예외를 덧붙여 Skill을 만듭니다. Explore More는 제거했으며 추가 기능은 웹앱 메뉴에서 접근합니다.

초보자 안내는 MinIO·버킷의 의미부터 도구 후보, 시험 실행, 대화, Record와 Skill의 역할을 단계별로 설명합니다. 탭을 처음 직접 열면 그 탭의 역할을 말풍선으로 짚고, 각 탭 상단에도 짧은 설명을 유지합니다.

말풍선의 **다음 단계**는 해당 단계의 실제 Discover·구성 열기·폼 제출·Record 동작으로 연결됩니다. 입력 오류는 기존 검증을 그대로 적용합니다. 직접 녹화하는 단계에서는 입력칸을 열고 포커스를 옮기며, 사용자가 웹앱에서 동작을 수행해야 진행됩니다. 처음 방문한 탭의 의미를 설명하는 동안에는 다음 단계를 누르면 본래 체험 안내로 돌아옵니다.

도구 탭은 모든 작업을 이름·한 줄 설명의 접힌 목록으로 보여줍니다. 항목을 펼치면 입력·예시·실행 결과를 확인할 수 있고, 펼침 상태는 실행 후에도 유지합니다. 도구 탭에는 목록만 두고, 체험 안내는 welcome card로 제공합니다. 각 도구를 펼쳐 해당 입력과 실행 버튼을 사용합니다. 기존의 ‘시험 필요/읽기’ 혼합 배지는 제거했습니다. 개인 Skill은 생성 후 가르치기 상단에 이름·배운 순서·바꿀 입력·실행 폼을 표시하며, 가르치기 탭의 Skill 표시로 다시 찾을 수 있습니다. Skill은 현재 Live Demo 메모리에만 유지되며 초기화 시 사라집니다.

메일은 검색·결과 확인·본문 읽기·발신자 필터·별표 추가·별표 해제·별표 모아보기 7개 작업을 제공합니다. Discover 후 각 도구에서 대상을 선택해 바로 실행할 수 있습니다. 검색 도구의 실행은 검색 흐름 확인도 겸합니다. 예: `구매팀 메일을 읽고 별표를 붙여서 모아줘`. 복합 요청은 합성 메일에서 대상을 찾고 작업을 순서대로 수행하며, 채팅에 단계별 결과를 표시합니다. 지원한 표현을 해석하는 데모 로직이며 실제 모델 호출은 아닙니다. Record의 대표 학습 시나리오는 메일 검색입니다.

세 체험 모두 Keeper가 닫힌 상태에서 시작합니다. 말풍선의 첫 단계는 주소창 오른쪽 확장 버튼을 눌러 패널을 여는 것이며, 이후 Discover부터 이어집니다(총 11단계). 버튼을 다시 누르면 패널만 닫히고 작업 상태는 유지됩니다.

도구 실행 결과는 왼쪽 웹앱의 결과 배너에 표시하며, 메일 검색·필터·별표·본문 읽기는 영향을 받은 행 또는 본문을 강조합니다. 메일 추가 도구 실행에는 선행 시험 잠금이 없습니다. 실제 Extension 권한이나 검증 규칙을 바꾼 것이 아닌 Live Demo UX 변경입니다.

가르치기는 ‘내 Skill’ 토글 목록과 ‘새로 가르치기’ 버튼을 중심으로 구성합니다. 녹화 후 이름·설명을 저장할 때마다 별도 Skill을 추가하며, 항목별 녹화 내역과 실행 입력을 보존합니다. 새 녹화 취소는 기존 Skill을 삭제하지 않습니다. 메일은 검색 외에도 별표 추가·해제, 본문 열기, 발신자 선택과 별표 모아보기를 녹화·재실행할 수 있습니다. 검색어는 재사용 시 변경 가능하고, 메일·발신자 대상은 녹화한 값으로 고정됩니다. 저장은 현재 체험 메모리 범위이며 사이트 변경·초기화·새로고침 시 사라집니다.
