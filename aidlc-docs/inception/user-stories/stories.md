# Vibe Zoo — User Stories

- **상태**: 승인된 [계획](../plans/story-generation-plan.md)에 따라 작성했으며 2026-09-08T09:27:45Z 사용자 승인을 확인했다. 모든 수용조건은 구현·실행 검증 전이다.
- **기준선**: [requirements.md](../requirements/requirements.md)의 FR-01~09, AC-01~10, NFR-01~08. 아래는 이를 사용자 결과로 구체화한 것으로 범위·기술 결정을 추가하지 않는다.
- **페르소나**: 모든 스토리는 [P-01](personas.md)을 사용하며 역할만 구분한다.
- **공통 조건**: 마지막 묶음의 CC-01~08을 한 번 정의한다. 각 스토리의 참조는 해당 조건을 수용조건에 포함한다는 뜻이다. 공통 조건을 기능별로 복사하지 않는다.
- **범위**: 첫 실제 전체 흐름은 MinIO Console이며 다른 미등록 사이트도 같은 추출 요청 경로를 사용한다. 공유·설치와 개선은 후순위 MVP로 포함한다. 별도 관리자 등록·CLI·Agent 앱, Native WebMCP·공개 API·사이트 코드 수정은 전제가 아니다.

## 1. 현재 사이트에서 도구 준비

### US-01 — 준비된 자산으로 바로 시작

**P-01 / 업무 실행자**로서, 현재 웹앱의 준비된 기능과 요청 예시를 확인해 다시 탐색하는 시간을 줄이고 싶다.

- **전제**: 현재 탭에 적용 가능한 개인 또는 공유 Preset이 있다. 개인 생성 자산 또는 US-07의 설치 결과로 준비할 수 있다.
- **연결**: FR-01, FR-06; AC-06; NFR-04, NFR-05.
- **공통 참조**: 연결 확인 CC-01, 상태 안내 CC-02, 필요한 자산 선택 CC-08.
- **수용조건**:
  - Given 호환 Preset이 있을 때, When Keeper를 열면, Then 적용 가능한 도구·기본 Skill·요청 예시가 표시되고 불필요한 전체 탐색은 시작하지 않는다.
  - Given 자산이 준비되어 있을 때, When 사용 준비 상태를 확인하면, Then 설치·검증 상태와 현재 로그인·실행 권한을 구분해서 확인할 수 있다.
  - Given 생성된 기본 Skill이 있을 때, When 개인 자산 설정을 열면, Then 기본 Skill을 확인할 수 있다.

### US-02 — 처음 만난 사이트에서 실행할 도구 만들기

**P-01 / 업무 실행자**로서, 준비된 도구가 없는 현재 사이트에서도 필요한 기능을 생성해 대화로 사용하고 싶다.

- **전제**: 호환 Preset이 없는 현재 탭. 접근 가능한 페이지 근거를 관찰하며 사이트 전체 지원을 가정하지 않는다.
- **연결**: FR-01, FR-02, FR-03; AC-01, AC-02, AC-04, AC-10; NFR-02, NFR-04, NFR-06.
- **공통 참조**: 관찰·검증 CC-01~03, 취소/이동 CC-04·06, 관찰 데이터 CC-07, 탐색 예산 CC-08.
- **수용조건**:
  - Given Preset이 없을 때, When Keeper를 열면, Then 관리자 사전 등록이나 필수 매뉴얼 입력 없이 같은 Panel의 Backend MCP 생성 흐름으로 진입한다. 다른 미등록 사이트에도 같은 요청 경로를 제공한다.
  - Given 실제 페이지 근거에서 기능을 찾았을 때, When 생성 결과를 확인하면, Then 도구 계약·실행 어댑터·성공 판정·기본 Skill·검증 근거·버전이 연결되고 기능별 상태는 CC-02로 구분한다.
  - Given 기능 후보가 생성됐을 때, When 관찰과 다른 입력으로 실제 실행을 검증하면, Then 검증된 기능부터 사용할 수 있고 불가능한 기능은 범위와 이유를 표시한다. 미리 숨겨 둔 사이트 전용 구현이나 모의 결과를 범용 생성 증거로 쓰지 않는다.

## 2. 같은 채팅에서 업무 실행

### US-03 — 요청한 업무를 내 탭에서 끝내기

**P-01 / 업무 실행자**로서, 하고 싶은 일을 채팅으로 요청하고 실제 업무 결과를 같은 채팅에서 확인하고 싶다.

- **전제**: 사용 가능한 도구·Skill과 연결된 사용자 탭. US-01·02·07의 결과 또는 동등하게 검증된 자산으로 독립 검증한다.
- **연결**: FR-04, FR-09; AC-03, AC-09; NFR-01, NFR-03, NFR-04, NFR-05.
- **공통 참조**: 실행 CC-01~03, 취소/단절 CC-04~06, 문맥 선택 CC-08.
- **수용조건**:
  - Given 필요한 도구가 준비됐을 때, When 업무를 요청하면, Then Backend Agent가 관련 Skill·도구를 선택하고 실제 MCP 검색·호출을 통해 자신의 탭에서 필요한 여러 단계를 수행한다.
  - Given 실행 결과가 돌아왔을 때, When 완료 응답을 받으면, Then CC-02에서 판정한 업무 결과와 실행 요약이 요청한 같은 채팅에 표시된다.
  - Given 필요한 도구가 없을 때, When 해당 업무를 요청하면, Then 누락 기능과 생성·시연 경로를 안내하며 업무를 수행한 것처럼 답하지 않는다.

## 3. 시연으로 개인 Skill 학습

### US-04 — 한 번 보여준 업무를 다른 입력으로 재사용

**P-01 / 업무 시연자**로서, 시연과 의도를 전달해 같은 업무를 다른 입력으로 다시 수행하는 개인 Skill을 얻고 싶다.

- **전제**: 현재 웹앱에서 시연 가능. 기존 도구를 조합할 수 있으며 누락 도구가 있으면 US-02의 생성 후보로 연결할 수 있다.
- **연결**: FR-03, FR-05; AC-04, AC-05; NFR-02, NFR-03.
- **공통 참조**: 시연·검증 CC-01~03, 취소/단절 CC-04~06, Record 데이터 CC-07.
- **수용조건**:
  - Given Record를 시작했을 때, When 업무를 시연하고 Stop 후 의도를 직접 입력하면, Then 기록 중 표시·수집 범위를 확인할 수 있고 관찰 가능한 기록과 의도가 Backend로 전달된다. 영상 전체 수집을 필수로 가정하지 않는다.
  - Given 기록과 의도가 전달됐을 때, When 초안을 받으면, Then 절차·바꿀 입력·기본값·성공 조건·의존 도구를 확인한다. 기존 도구로 수행 가능한 시연은 해당 도구를 조합한 Skill로 만들고, 새 원자 기능이 필요할 때는 생성 후보 또는 미지원 단계로 표시한다.
  - Given 실행 가능한 초안이 있을 때, When 시연과 다른 입력으로 검증하면, Then 검증을 통과한 개인 Skill을 저장해 같은 채팅에서 재사용한다. 검증 실패·의존 도구 미준비 상태는 초안으로 구분하고 준비 완료로 표시하지 않는다.

## 4. 개인 자산 편집·재사용

### US-05 — 내 설정을 저장하고 다음 업무에 적용

**P-01 / 업무 실행자**로서, Skill의 이름·설명·기본값·사용 여부를 내 방식에 맞게 정하고 다음 접속에서도 유지하고 싶다.

- **전제**: US-04로 검증한 개인 Skill 또는 동등한 개인 자산이 있다. Store 가입·게시가 필요하지 않다.
- **연결**: FR-06, FR-09; AC-05, AC-06; NFR-03, NFR-05.
- **공통 참조**: 후속 실행 CC-01~03, 새로고침·재접속 CC-05·06.
- **수용조건**:
  - Given 개인 자산이 있을 때, When 설정을 열면, Then 현재 사이트 적용 자산과 의존 도구·호환성·준비 상태·사용 버전을 확인한다.
  - Given 이름·설명·기본 입력값·활성 상태를 편집했을 때, When 저장 후 새로고침·재접속하면, Then 변경값이 유지되고 다음 채팅 실행에 반영된다. 비활성 Skill은 실행 선택에서 제외된다.
  - Given 검증된 개인 Skill의 기본 입력값을 바꿨을 때, When 다음 업무에 재사용하면, Then 바뀐 입력이 적용된 결과를 확인한다. Store 게시 없이 이 흐름이 완료된다.

## 5. 자산 공유·설치

### US-06 — 선택한 버전을 동료에게 공유

**P-01 / 자산 공유자**로서, 내가 선택한 자산 버전과 검증 범위를 공유해 동료가 사용할 수 있게 하고 싶다.

- **전제**: 공유자가 소유·사용하는 버전 있는 도구·Skill 자산이 있다. US-02·04·08의 결과를 사용할 수 있다.
- **연결**: FR-07; AC-07; NFR-02, NFR-05, NFR-08.
- **공통 참조**: 게시 결과 CC-02, 공유 데이터 CC-07.
- **수용조건**:
  - Given 개인 자산이 있을 때, When 생성하거나 편집만 하면, Then 자동 게시되지 않는다. 공유자가 자산·버전을 선택해 게시했을 때만 별도 Store에 공유된다.
  - Given 게시가 완료됐을 때, When Store에서 해당 자산을 탐색하면, Then 설명·작성자·버전·적용 대상·의존 도구·검증 범위를 확인한다.

### US-07 — 공유받은 자산을 내 환경에서 검증

**P-01 / 자산 설치자**로서, 동료의 자산을 내 계정에서 검증해 별도 생성 작업을 줄이고 싶다.

- **전제**: US-06으로 공유된 특정 버전 또는 동등한 공유 자산이 있다. 공유자와 설치자는 서로 다른 사용자·세션이다.
- **연결**: FR-01, FR-07; AC-07; NFR-01, NFR-02, NFR-06.
- **공통 참조**: 설치 후 검증 CC-01~03, 단절/재접속 CC-04~06, 자산 데이터 CC-07.
- **수용조건**:
  - Given 공유 자산을 찾았을 때, When 특정 버전을 설치하면, Then 그 버전과 의존성을 자신의 개인 자산에서 확인하고 자신의 로그인된 탭에서 호환성과 실행을 검증한다.
  - Given 설치된 자산이 있을 때, When 로그인·권한·호환성 또는 실행 검증이 충족되지 않으면, Then 설치 상태와 실행 가능 상태를 구분하고 필요한 조치를 표시한다. 공유자의 세션을 제공하거나 대신 실행하지 않는다.

## 6. 실패에서 개선

### US-08 — 개선을 검증하며 정상 버전 유지

**P-01 / 업무 실행자**로서, 실패·수정·추가 시연을 개선에 활용하면서 이미 잘 되던 업무를 유지하고 싶다.

- **전제**: 현재 자산 버전, 재현 가능한 실패와 관련 성공 사례가 있다. US-02·04·07의 자산으로 검증할 수 있다.
- **연결**: FR-08; AC-08; NFR-03.
- **공통 참조**: 재검증 CC-01~03, 중단/버전 일관성 CC-04~06, 개선 근거 CC-07.
- **수용조건**:
  - Given 재현 실패·사용자 수정·추가 시연을 근거로 개선을 요청했을 때, When 후보가 생성되면, Then 실패 원인·변경 이유·새 버전을 확인하며 현재 사용 버전과 구분한다.
  - Given 개선 후보가 있을 때, When 검증하면, Then 해당 실패와 관련 기존 성공 사례를 함께 재검증하고 버전별 결과를 보존한다. 미검증 변경을 조용히 적용하지 않는다.
  - Given 후보 검증 또는 변경 적용이 실패했을 때, When 사용 버전을 확인하면, Then 정상 버전이 유지되거나 이전 버전으로 되돌릴 수 있다. 모델 파인튜닝이나 완전 자율 운영을 요구하지 않는다.

## 7. 중단·재접속과 실행 대상 보호

### US-09 — 멈춘 업무의 상태를 알고 이어가기

**P-01 / 업무 실행자**로서, 작업이 멈춰도 발생한 결과와 다음 행동을 이해하고 올바른 탭에서 이어가고 싶다.

- **전제**: 진행 중이거나 중단된 관찰·생성·검증·실행 작업이 있다. 앞선 스토리의 해당 상태로 독립 검증한다.
- **연결**: FR-02, FR-04, FR-09; AC-09; NFR-01, NFR-03, NFR-04, NFR-05.
- **수용조건**: 사용자 취소는 CC-04, 로그인 만료·단절·권한 부족은 CC-01·05, 페이지 이동·재연결·버전 변경은 CC-01·06, 부분 완료·지원 불가는 CC-02, 긴 생성·탐색 한도는 CC-08의 Given/When/Then으로 검증한다. 결과를 다시 복사하지 않고 아래 정의를 직접 참조한다.

### 공통 수용조건

#### CC-01 — 실행 대상과 권한

Given 관찰·실행 요청이 있을 때, When 브라우저 작업을 전달하거나 재개하면, Then 사용자·Extension 연결·탭·문서/페이지 상태·출처·작업·자산 버전과 필요한 권한을 확인하고 현재 대상을 표시한다. 불일치·권한 부족 시 진행하지 않으며 다른 사용자·관리자 환경으로 대체하지 않는다. 다른 사이트로 넘길 경우 대상 탭의 연결·권한을 별도로 확인한다. (NFR-01)

#### CC-02 — 업무 결과와 상태 안내

Given 작업 결과를 받았을 때, When 성공 여부를 표시하면, Then 관찰 가능한 업무 사후 상태로 판정한다. HTTP 성공·클릭·예외 없음만으로 성공 처리하지 않는다. 후보·미검증·실행 가능·지원 불가·실패·중단·부분 완료·결과 확인 실패를 해당 맥락에 맞게 구분한다. Extension 작업은 같은 Panel에서, Store 작업은 해당 웹 화면에서 이유와 다음 행동을 안내한다. (NFR-03, NFR-05)

#### CC-03 — 변경 전 확인

Given 탐색·시연 학습 후 검증·업무 실행 중 상태 변경이 필요할 때, When 변경을 수행하려 하면, Then 대상과 변경 내용을 보여주고 필요한 사용자 확인을 받은 후 수행한다. 탐색을 이유로 사용자 모르게 변경하지 않는다. (FR-04)

#### CC-04 — 취소와 늦은 결과

Given 작업 진행 또는 명령 전달 이후일 때, When 사용자가 취소하면, Then 새 작업 전달을 중단하고 이미 발생한 결과를 확인해 표시한다. 취소가 기존 변경을 되돌렸다고 가정하지 않으며 늦은 결과를 자동 활성화하지 않는다. (FR-02, NFR-03)

#### CC-05 — 단절 후 재개

Given 연결 단절·로그인 만료·실행 상태 불확실성으로 멈췄을 때, When 연결·로그인·권한이 복구되면, Then CC-01을 다시 확인하고 이미 수행된 변경의 실제 결과를 조회한 뒤 재시도·재개 여부를 판단한다. 미확인 상태에서 변경을 반복하지 않는다. (NFR-03)

#### CC-06 — 대화·작업·자산의 일관성

Given 같은 사용자의 대화·장기 작업·설치 자산이 있을 때, When 새로고침·탭/문서 이동·재접속·자산 버전 변경이 발생하면, Then 브라우저 연결과 각 상태를 구분해 이어가고 동일 사이트·작업을 중복 생성하지 않는다. 진행 중인 작업을 새 탭·출처·버전으로 임의 전환하지 않으며 실행 전 CC-01을 다시 확인한다. (FR-09, NFR-03)

#### CC-07 — 관찰·개인·공유 데이터 경계

Given 비민감 행동과 민감 입력이 함께 있는 합성 관찰·Record 자료를 사용할 때, When 자산 생성·개선·전송·저장·공유를 수행하면, Then 필요한 범위만 수집하고 민감 입력은 제외한다. 자산에는 비밀번호·토큰·쿠키·인증 헤더·개인 브라우저 프로필을 포함하지 않고 원본 시연·개인 대화·인증정보를 함께 공개하지 않는다. 전송·저장·삭제의 구체적 경계는 NFR-02의 후속 설계 대상으로 유지하고 그 경계에서 데이터가 제거·분리되는지를 확인한다. 공개 예시·검증 증거는 NFR-08을 따른다.

#### CC-08 — 긴 작업과 탐색 한도

Given 긴 생성·탐색 또는 여러 요청이 있을 때, When 작업을 진행하면, Then 시간·행동 수·토큰·재시도에 설정된 상한과 취소를 적용하며 긴 생성이 일반 채팅·기존 기능 사용을 계속 막지 않는다. 현재 사이트·요청에 필요한 도구·Skill만 선택한다. 한도 도달 시 CC-02를 따른다. 구체적 수치·worker·서버 사양은 후속 근거로 결정한다. (NFR-04)

## 공통 완료 기준과 검토

모든 스토리의 UI 표현은 NFR-05를, 실제 실행·오류 처리·설정 분리·의존성/락파일·간단한 CI는 NFR-07을, 공개 데이터·증거는 NFR-08을 참조한다. 실제 제품 스크린샷을 루트 `screenshots/` 또는 `result/`에 저장하고 검증된 기능과 README를 일치시키는 제출 기준은 requirements.md 6절을 적용한다. 모의 화면·타이머·고정 데이터는 실제 제품 검증 증거가 아니다.

각 스토리는 전제 자산·상태를 준비해 결과 단위로 검증할 수 있으며, 실제 전체 흐름의 연결 검증도 유지한다. 이는 의존성이 없다는 주장이 아니다. INVEST의 협의 가능성은 구현 방식에 적용하고 승인된 범위를 줄이지 않는다. Backend 기술·엔진·배포·지원 행렬은 미정으로 유지한다.
