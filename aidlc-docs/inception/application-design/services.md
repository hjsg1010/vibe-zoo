# Vibe Zoo — Services and Orchestration

**상태**: 원문 재검토 후 승인된 Application Design. 서비스는 [C-03](components.md)이 조정하는 사용자 업무 흐름이며 별도 서버·컨테이너를 뜻하지 않는다. 입출력 타입은 [공통 계약](component-methods.md), 수용조건은 [stories.md](../user-stories/stories.md)의 정의를 참조한다.

## 1. 공통 조정

C-03은 대화·장기 작업·브라우저 연결 상태를 구분해 보존하고, 자산·설정·버전은 C-06에 맡긴다. 브라우저 요청은 C-03의 현재 ExecutionControl과 C-02의 최종 대상 확인을 통과한다. C-05는 실제 실행과 사후 상태 검증을 연결한다. C-04의 후보·추가 관찰/변경 제안은 조정자에게 돌아온다.

긴 작업의 접수와 결과를 분리하고 진행·확인 요청·중단·결과를 원래 화면에 전달한다. 동시 처리·재접속·재시도·중복 방지·예산의 상세 규칙은 CC-04~06·08을 적용해 해당 유닛에서 설계한다. 하나의 작업을 유지하기 위해 새 문서/탭에 기존 실행 허가를 전용하지 않는다.

C-03과 C-06이 반영하는 자산 결과는 현재 작업·대상·후보 버전·검증 근거와 연결한다. 늦은 결과의 보존과 활성화를 구분하며 이미 발생한 외부 변경은 WorkOutcome으로 보고한다. 기술적으로 어떤 저장소·queue·worker가 이를 구현하는지는 미정이다.

## 2. 서비스별 책임과 흐름

### S-01 — 도구 준비 / US-01·02

- **입력 → 출력**: ActorContext + BrowserTarget → AssetView 또는 생성 JobView.
- C-01 → C-03 → C-06으로 호환 개인/공유 자산을 확인한다. 사용 가능한 자산을 선택해 준비 상태와 현재 사용자 실행 조건을 구분한다. 공유 자산이 설치되지 않았다면 S-05의 특정 버전 설치·자체 검증 경로를 적용한다.
- 호환 자산이 없으면 C-03이 같은 Panel의 생성 작업을 시작한다. C-02 관찰 → C-04 MCP Generator 후보 → C-06 후보 저장 → C-05 검증 → C-03/C-06 결과 반영으로 이어진다.
- 추가 근거가 필요하면 C-04 요청을 C-03이 조정한다. 전체 탐색 전 검증한 기능부터 사용 가능하게 하며 다른 입력 검증·미지원 이유를 근거에 연결한다.
- **공통 참조**: US-02에 연결된 CC-01~04·06~08. 최초 MinIO Console과 다른 미등록 사이트의 요청 경로를 분기된 전용 제품으로 만들지 않는다.

### S-02 — 채팅 실행 / US-03

- **입력 → 출력**: 대화 요청 + BrowserTarget → 같은 대화의 JobView 및 WorkOutcome.
- C-03의 Keeper Agent가 C-06의 개인 활성 설정·관련 Skill을 읽고 C-05의 실제 MCP 도구 검색을 이용한다.
- 선택한 버전과 입력을 고정한 MCP 호출 → C-02 지정 동작 → C-02 사후 상태 관찰 → C-05 판정 → C-03/C-01 결과 표시로 이어진다. 필요하면 다음 업무 단계를 반복한다.
- 변경이 필요한 경우 C-03/C-01이 ChangeProposal을 표시하고 Confirmation을 받는다. 필요한 도구가 없으면 생성·시연 경로를 안내한다.
- **공통 참조**: US-03의 CC-01~06·08. 클릭 완료·전송 성공은 업무 성공 판정이 아니다.

### S-03 — 시연 학습 / US-04

- **입력 → 출력**: RecordData + 사용자 명시적 의도 + 의존 도구 → 초안 또는 검증된 개인 Skill의 AssetView.
- C-01/C-02 Record 시작 → 사용자 시연 → Stop → 의도 입력 후 최소 기록 전송 → C-03/C-04 개인 Skill 초안 순서다.
- C-04는 준비된 도구를 조합하고 없는 원자 기능은 S-01 후보 또는 미지원 단계로 돌려준다. C-03/C-06은 초안을 후보로 보존한다.
- C-05에서 시연과 다른 입력으로 검증하고 C-03/C-06이 결과에 따라 개인 사용 상태를 반영한다. 실패·누락 의존성은 초안에 표시한다.
- **공통 참조**: US-04의 CC-01~07. 학습의 검증 실행에도 변경 전 확인과 같은 사용자 탭 경계를 적용한다.

### S-04 — 개인 설정 / US-05

- **입력 → 출력**: 본인 자산 버전 + 설정 변경 → 저장된 AssetView.
- C-01 → C-03 → C-06으로 이름·설명·기본값·활성 상태를 저장한다. 다음 채팅에서 C-03이 해당 개인 설정을 적용하며, 실행 가능 여부는 공통 계약의 updateSettings/activate 구분을 따른다.
- 생성된 기본 Skill도 조회 대상이다. 자산·의존성·버전·준비 상태를 보여주고 새로고침·재접속 후 유지한다.
- **공통 참조**: US-05의 CC-01~03·05·06. 저장 기술과 수정 내용별 검증 영향은 후속 설계에서 정한다.

### S-05 — 공유·설치 / US-06·07

- **입력 → 출력**: 공유자의 명시적 버전 선택 또는 설치자의 특정 공유 버전 선택 → 게시/설치 AssetView 및 자체 검증 JobView.
- C-07 또는 C-01의 공유 진입점 → C-03 → C-06으로 선택 버전의 공유 가능 항목만 게시한다. C-07에서 설명·작성자·적용 대상·의존성·검증 범위를 탐색한다.
- 설치 요청은 설치자의 개인 영역에 특정 버전·의존성을 기록한다. 자신의 연결된 Keeper에서 C-03/C-05/C-02 검증을 거쳐 실행 가능 여부를 확인한다.
- 연결되지 않은 경우 설치 상태와 연결/로그인/검증의 다음 행동을 안내한다. 공유자의 검증 근거를 설치자의 실행 권한이나 자체 검증으로 취급하지 않는다.
- **공통 참조**: US-06·07에 지정된 CC. 서로 다른 사용자·세션으로 검증하며 개인 학습·실행은 Store 게시 절차에 의존하지 않는다.

### S-06 — 검증된 개선 / US-08

- **입력 → 출력**: 현재 버전 + 재현 실패/관련 성공 사례 + 선택적 수정 또는 추가 시연 → 이유가 설명된 후보와 버전별 ValidationReport. 수정·추가 시연 없이도 재현 실패와 관련 성공 근거로 후보 생성을 시작할 수 있다.
- C-03이 C-06의 현재 버전과 필요한 근거를 모아 C-04에 전달한다. 변경 이유가 있는 새 후보를 C-06에 저장한다.
- C-05는 재현 실패와 관련 기존 성공 사례를 함께 재검증하고 C-03/C-06이 결과를 버전에 연결해 보존한다.
- 검증 범위와 변경을 드러낸 뒤 사용 버전을 적용한다. 실패하면 현재 정상 버전을 유지하거나 C-06의 이전 버전 선택으로 복구한다. 세부 적용 조건은 Functional Design에서 정한다.
- **공통 참조**: US-08의 CC-01~07. 취소·단절·미확인 결과로 후보가 조용히 활성화되지 않도록 한다.

## 3. 중단·복구 / US-09

US-09는 별도의 업무 서비스를 추가하기보다 위 브라우저 작업 서비스의 C-03 제어와 C-02/C-05 경계에서 처리한다. C-03은 취소 이후 새 전달을 중단하고, 재연결 때 대상과 이미 발생한 결과를 다시 확인한다. 일관성·실패 표시의 기준은 CC-01~06·08에서 한 번 정의한 내용을 따른다. 자동 보상 실행이나 모든 사이트간 자동 연쇄를 추가하지 않는다.
