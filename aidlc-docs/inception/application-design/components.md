# Vibe Zoo — Components

- **상태**: 2026-09-08T09:51:33Z 원문 재검토 조건 충족으로 Application Design 승인 확인. 실제 구현·연동 완료를 뜻하지 않는다.
- **범위**: 아래 7개는 논리 책임이며 서버·프로세스·개발 유닛·담당자 수가 아니다. Backend 기술·제품 모델·전송·저장소·어댑터 표현·배포는 미정이다.
- **참조**: 공통 계약과 메서드 입출력은 [component-methods.md](component-methods.md), 조정 흐름은 [services.md](services.md), 의존성은 [component-dependency.md](component-dependency.md)에 정의한다. 수용조건은 [stories.md](../user-stories/stories.md)의 US/CC를 참조한다.

## C-01 — Keeper UI

**목적**: 현재 웹앱의 준비·실행·학습·개인 설정을 같은 Side Panel에서 이어준다.

- **책임**: 도구와 Skill의 준비 상태, 요청 예시, 채팅·진행 결과, Record 제어, 개인 설정, 실행 대상과 변경 확인을 표시한다. 준비된 자산과 현재 로그인·권한을 구분하며 화면의 모의 상태로 성공을 결정하지 않는다.
- **인터페이스 의미**: 현재 대상 확인·선택과 Record 제어는 C-02에 전달한다. 관찰 기록과 의도 전달, 채팅·생성·설정 등 모든 Backend 업무는 C-03에 요청하고 그 결과·진행·확인 요청을 표시한다. 자산 활성·게시 상태를 화면에서 임의 확정하지 않는다.
- **스토리/공통 조건**: US-01~05·09; CC-01~06·08. Record의 데이터 경계는 CC-07을 따른다.

## C-02 — Browser Bridge / Recorder

**목적**: 요청한 사용자의 실제 브라우저 탭에서 관찰·기록·지정 실행을 수행한다.

- **책임**: 현재 대상과 문서 상태, 접근 가능한 페이지 근거, 필요한 시연 기록과 업무 사후 상태를 제공한다. 브라우저 작업 직전에 대상·출처·문서·권한을 최종 확인하며, 불일치나 접근 불가를 다른 사용자 환경으로 대체하지 않는다.
- **인터페이스 의미**: C-01의 대상·Record 제어, C-03의 관찰·결과 재확인, C-05의 제어 문맥에 연결된 실행·사후 관찰 요청을 받는다. 관찰·기록·실행 결과 또는 지원 불가·단절·문서 변경을 회신한다. 민감 입력은 Backend 전송 전에 제외한다. 생성 모델의 임의 지시를 직접 받아 실행하지 않는다.
- **스토리/공통 조건**: US-02~05·07~09; CC-01~07. 실행 형식과 수집 신호는 후속 설계·기술검증 대상이다.

## C-03 — Keeper Orchestrator

**목적**: 사용자 요청을 해석하고 업무 흐름과 현재 실행 문맥을 일관되게 조정한다.

- **책임**: Keeper Agent의 요청 해석·Skill/도구 선택·다단계 업무 진행을 담당한다. 대화·Extension 연결·장기 작업 상태의 저장과 조회를 소유하며, 진행·취소·재접속·실행 확인과 탐색 예산을 조정한다. 이 상태들은 자산과 브라우저 연결 자체를 혼동하지 않고 관리한다.
- **인터페이스 의미**: C-01과 C-07의 Backend 요청을 받고, C-06에서 필요한 자산·설정을 조회해 C-04에 관찰 근거와 자산 문맥을 제공한다. 추가 근거·검증 제안을 평가해 C-05에 유효한 작업 제어 문맥을 전달한다. C-06에 후보·검증 결과·설정 변경을 기록하고, 확인된 근거와 사용자 선택에 따라 활성·게시 변경을 요청한다.
- **스토리/공통 조건**: US-01~09; CC-01~08. Extension 업무는 같은 Panel로, Store 업무는 Store 화면으로 결과를 돌려준다. 모델·worker·작업 저장 기술은 정하지 않는다.

## C-04 — Generation / Learning

**목적**: 관찰과 명시적 의도를 재사용 가능한 도구·Skill 후보로 바꾼다.

- **책임**: 명시적 MCP Generator 역할, 기본·개인 Skill 초안 생성, 실패·수정·추가 시연에 근거한 개선 후보 생성을 담당한다. 도구 계약·어댑터·성공 조건·기본 Skill과 근거·버전의 연결을 제안하며, 기존 도구로 가능한 업무는 해당 도구의 조합으로 표현한다.
- **인터페이스 의미**: C-03이 제공한 관찰·시연·의도·자산·검증 근거를 입력받아 후보, 추가 근거 요청 또는 검증 제안만 반환한다. C-02나 C-06에 직접 접근하지 않고, 브라우저 실행·자산 저장·활성·게시를 결정하거나 수행하지 않는다. 제안된 성공 조건은 실제 검증 결과를 대신하지 않는다.
- **스토리/공통 조건**: US-02·04·08; CC-02·07·08. 실제 브라우저 검증과 취소 처리는 C-03·C-05를 통해 연결한다.

## C-05 — MCP Execution / Validation

**목적**: 도구 계약을 실제 MCP 검색·호출과 사용자 브라우저의 업무 결과에 연결한다.

- **책임**: 요청 사용자에게 적용되는 도구 검색, 버전이 지정된 도구 호출, 관찰·실행 및 업무 사후 상태 검증을 담당한다. 생성·Skill 학습·일상 실행·설치·개선은 이 공통 실행·검증 경로를 사용한다.
- **인터페이스 의미**: C-03이 전달한 제어 문맥으로 매 작업의 대상·취소·확인 상태와 유효성을 확인한다. C-06에서 해당 도구·어댑터·검증 조건의 버전을 조회하고, C-02에 관찰·실행을 요청해 결과와 검증 근거를 C-03에 반환한다. 직접 자산을 활성화·게시하거나 HTTP 성공만으로 업무 성공을 결정하지 않는다.
- **스토리/공통 조건**: US-02~05·07~09; CC-01~06·08. 실제 MCP 연결을 유지하며 transport·어댑터 실행 기술은 미정이다.

## C-06 — Asset Registry / Personal Settings

**목적**: 재사용 가능한 자산과 개인 설정, 검증·버전의 기준 정보를 관리한다.

- **책임**: 도구·Skill·의존성·적용 대상·검증 근거·버전·개인 기본값·활성 상태 및 공유·설치 관계를 저장·조회한다. 후보와 사용 버전, 설치 여부와 실행 가능 상태, 개인 데이터와 공유 자산을 구분한다. 대화·연결·장기 작업 상태의 소유자는 C-03이다.
- **인터페이스 의미**: C-03의 자산·설정·후보·검증 기록 및 공유·설치 요청과 C-05의 버전 조회를 제공한다. 활성·게시 변경은 C-03의 요청으로만 반영한다. C-04의 후보 생성이나 검증 결과 수신만으로 사용 버전을 바꾸지 않으며, 이전 버전과 검증 결과를 보존한다.
- **스토리/공통 조건**: US-01~08; CC-02·04·06·07. 저장소 종류와 세부 보존·삭제 정책은 후속 설계 대상이다.

## C-07 — Store UI

**목적**: 공유 자산을 탐색하고 선택한 버전을 게시·설치하는 별도 웹 경험을 제공한다.

- **책임**: 자산 설명·작성자·버전·적용 대상·의존성·검증 범위를 표시하고 명시적인 공유·설치 선택을 받는다. 설치자의 로그인·권한과 자산 설치를 구분하며 개인 Keeper 사용의 필수 진입 화면이 되지 않는다.
- **인터페이스 의미**: 모든 Store 업무는 C-03에 요청하고 게시·설치 결과와 필요한 조치를 Store 화면에 표시한다. C-06이나 다른 사용자의 브라우저에 직접 접근하지 않는다. 설치 후 실행 검증은 C-03이 설치자 자신의 연결로 조정한다.
- **스토리/공통 조건**: US-06·07; CC-02·07. 설치 검증에는 C-03·C-05·C-02의 CC-01~06이 적용된다.

## 경계 요약

현재 웹앱은 Vibe Zoo가 수정하는 내부 컴포넌트가 아니라 관찰·실행 대상이다. C-03은 C-02에 관찰·결과 재확인을 직접 요청할 수 있다. 상태를 변경할 수 있는 동작과 검증 실행은 C-03의 조정 및 C-05의 실행·검증을 거쳐 C-02에서 최종 대상 확인 후 수행한다. C-01의 직접 C-02 연결은 현재 대상과 사용자 시연 제어를 위한 것이다.

C-04의 생성 결과는 후보이며 C-05의 실제 검증과 C-03의 작업·선택 확인을 거쳐 C-06의 사용 상태에 반영된다. 어느 컴포넌트도 자산 설치를 사용자 로그인이나 웹앱 권한 제공으로 취급하지 않는다. 상세 상태 전이·비즈니스 규칙·기술 선택과 유닛 분할은 이 문서에서 확정하지 않는다.
