# Vibe Zoo — Requirements Analysis 확인 질문

제품 경험과 MVP 범위는 확정 입력으로 유지합니다. [요구사항](../../../requirements/vibe-zoo-requirements.md)과 [제약사항](../../../requirements/constraints.md), HTML 시안 두 개를 검토한 결과, 이 단계에서 다시 결정해야 할 제품 범위의 충돌은 발견하지 못했습니다. Backend 기술·엔진·배포 방식은 후속 설계와 작은 전체 흐름 기술검증에서 결정합니다.

이번 질문은 아직 선택하지 않은 AI-DLC 확장 3종에 한정합니다. 각 `[Answer]:` 뒤에 선택 문자를 입력해 주세요. 추천은 사용자 답변이나 승인으로 간주하지 않습니다. 다른 적용 범위를 원하면 X와 구체적인 범위를 적어 주세요.

보안·복원력 확장을 끄더라도 최소 인증·실행 권한, 사용자/탭/문서 경계, 민감정보 제외, 입력 검증, 실패·취소·재접속 처리와 실제 결과 검증은 기존 제품 요구사항으로 유지됩니다. 운영 보안 고도화·고가용성·재해복구는 현재 범위 밖입니다. 활성화한 확장에 이 범위와 충돌하는 규칙이 있으면 충돌과 영향을 설명하고 변경 의도를 확인하며, 범위를 자동 확대하지 않습니다.

## Question 1 — Security Baseline

이 프로젝트에 SECURITY 확장 규칙을 적용할까요?

**추천: B.** 이번 해커톤은 제약사항에 명시된 기본 품질과 실행 경계를 구현하는 데 집중합니다. A를 선택하면 해당 확장 전문을 읽고 적용 가능한 SECURITY 규칙을 단계 완료의 필수 조건으로 검토합니다.

A) 예 — 모든 적용 가능한 SECURITY 규칙을 차단 조건으로 적용한다. 운영 수준 애플리케이션에 적합한 선택이다.

B) 아니요 — SECURITY 확장 규칙을 적용하지 않고, 확정된 제품 요구사항과 제약사항의 기본 품질을 구현한다.

X) 기타 — 원하는 적용 범위를 아래에 설명한다.

[Answer]: B

## Question 2 — Resiliency Baseline

이 프로젝트에 Resiliency Baseline을 적용할까요?

이 확장은 AWS Well-Architected Reliability Pillar와 복원력 검토 지침에 기반한 설계 지침입니다. 비즈니스 목표, 변경 관리, 관찰 가능성, 고가용성, 재해복구, 지속 개선을 포함한 15개 실천 영역을 다룹니다. 적용 자체가 운영 준비 완료나 가용성·RTO·RPO 목표 달성을 보장하지 않으며, 실제 시스템 검증과 정식 Well-Architected Review를 대신하지 않습니다.

**추천: B.** 현재 범위는 1박 2일 MVP이며 운영용 고가용성·재해복구는 제외되어 있습니다. 취소·연결 단절·로그인 만료·부분 완료의 정확한 처리는 확장 선택과 관계없이 구현합니다.

A) 예 — 복원력 기준을 설계 지침으로 적용한다. 업무 중요도가 높은 시스템에서 검증·보완할 초기 설계 기준으로 사용한다.

B) 아니요 — Resiliency Baseline을 적용하지 않고, 확정된 실패·중단·재접속 요구사항을 구현한다.

X) 기타 — 원하는 적용 범위를 아래에 설명한다.

[Answer]: B

## Question 3 — Property-Based Testing

이 프로젝트에 속성 기반 테스트(PBT) 확장 규칙을 적용할까요?

PBT는 여러 생성 입력에 대해 항상 성립해야 하는 성질을 검사하는 테스트 방식입니다. Partial은 순수 함수와 직렬화 왕복에만 적용 범위를 제한합니다.

**추천: C.** 이번 MVP의 우선 검증 대상은 실제 MCP·브라우저 연결, 새로운 입력으로 재사용, 실패·취소와 잘못된 세션 방지입니다. 선택형 PBT 규칙을 필수로 추가하지 않고 이 검증에 집중할 수 있습니다. B는 순수 함수와 직렬화 계약에 한정해 PBT를 필수 적용하려는 경우의 대안입니다. C도 핵심 테스트를 생략한다는 뜻은 아닙니다.

A) 전체 적용 — 모든 적용 가능한 PBT 규칙을 차단 조건으로 적용한다. 비즈니스 로직·데이터 변환·직렬화·상태를 다루는 구성요소에 적합하다.

B) 부분 적용 — 순수 함수와 직렬화 왕복에만 PBT 규칙을 필수 적용한다.

C) 적용 안 함 — PBT 확장 규칙을 적용하지 않고, 핵심 수용조건에 필요한 테스트를 수행한다.

X) 기타 — 원하는 적용 범위를 아래에 설명한다.

[Answer]: C
