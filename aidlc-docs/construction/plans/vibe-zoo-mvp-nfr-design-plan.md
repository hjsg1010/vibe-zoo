## 2. 다섯 질문 범주 평가

| 범주 | 설계에서 답할 질문 | 이미 승인된 근거와 처리 |
|---|---|---|
| Resilience | 취소·응답 유실·재시작 때 어디까지 재개하는가? | NFR 5절, BR-08~09: 취소 단조 유지, 전달된 변경은 관찰 후 판정, 제한 재시도. 원자적 판정과 복구 방식은 이 단계에서 설계하며 추가 사용자 질문 없음. |
| Scalability | 단일 서버에서 어떤 실행을 함께 처리하는가? | NFR 1·5절: 공용 Backend 하나, 같은 탭 충돌 조정, 긴 생성 중 채팅. 외부 큐·사용자별 컨테이너 없이 비동기 스케줄링을 설계하며 성장/부하 목표는 묻지 않음. |
| Performance | 탐색·모델 비용을 어떻게 제한하는가? | 승인된 Job 예산과 자산 선택 재사용을 설계에 반영. 실제 SLA·서버 사양·크레딧 보장은 없으며 새 수치 선택 질문 없음. |
| Security | 참여자·실행 대상·전송 자료를 어떻게 구분하는가? | Q2~Q3, NFR 4절, BR-01~05·10·12·15: 참여자별 데모 자격, 자기 탭, 합성 MinIO의 최소 근거만 전송. 확인된 경계를 구현할 기본 인증·투영·검사 방식을 설계하며 운영 보안 범위를 추가하지 않음. |
| Logical Components | 기존 역할에 어떤 저장·전송·작업 책임을 배치하는가? | 승인 기술 기준과 C-01~07: Node 단일 애플리케이션, Converse, 실제 MCP, HTTPS/WSS, SQLite. 물리 호스트/TLS 종료/지속 디스크는 Infrastructure Design에서 실제 환경과 연결. 현재 논리 설계에 추가 사용자 결정 없음. |

**답변 처리**: 기존 승인이 다섯 범주의 사용자 의도를 해소한다. 새로운 질문과 빈 `[Answer]:` 항목을 만들지 않는다. 기본 구현 선택은 아래 산출물로 검토받는다. 실제 공용 자원은 후속 인프라 단계의 확인 조건이며 존재한다고 가정하지 않는다. 충돌하는 요구가 드러나면 사용자의 원칙대로 차이·영향을 설명하고 한 번에 한 질문으로 확인한다.
