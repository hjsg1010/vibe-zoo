# U-01 구현·검증 기록

Code Generation Part 2 진행 중. 원본 수용조건은 [stories.md](../../../inception/user-stories/stories.md)를 참조한다. 실제 제품 검증은 아래에 별도로 기록한다. 단위/합성 검사를 실제 브라우저·모델 성공 증거로 사용하지 않는다.

## 기반·Repository

프로젝트 한정 Node 24.20.0 공식 배포 체크섬을 확인하고 npm 의존성을 정확한 버전과 lockfile로 설치했다. 전역 런타임은 변경하지 않았다. 공통 strict schema는 제한 동작·고정 실행 문맥·도구 묶음을 정의하며 Backend 전용 설정이 루트 .env를 읽는다. .env·런타임·SQLite·TLS·빌드 산출물은 Git 제외다.

SQLite는 WAL/FULL/외래 키와 버전 migration을 사용한다. Repository가 개인 소유 경계, 중복 접수, 불변 버전, 조건부 제어·설정 반영, 실제 결과 보존을 담당한다. 트랜잭션 내부 비동기 실행은 거절한다.

검사: `tests/backend/repository.test.ts` 7개 통과, `npm run typecheck` 통과. 사용자 격리·다른 입력의 중복 키·동일 생성의 대상 보존·취소/활성화·off/설정 충돌·실패/커밋 rollback·파일 DB 재열기·소유자 삭제 후 늦은 반영을 검사했다. 합성 데이터만 사용했다.

## 업무·API·Frontend

Coordinator가 사용자별 고정 대상/버전, 제어 revision, 변경 확인, 취소와 전달 순서를 조정한다. ModelScheduler는 생성/채팅 슬롯을 분리하고 소유자 순서를 순환한다. 예산 예약은 SQLite에 보존하며 응답 usage 미확인 시 예약을 유지한다. 미확인 동작은 대상 슬롯을 잡아두고 재전송 대신 기존 사후 조건의 읽기 전용 reconcile을 제공한다.

API는 해시된 접근 코드·만료 세션, Extension Origin·자격 인증, 256 KiB 상한, 소유 경계·제어 충돌을 검사한다. Backend는 HTTPS, 브리지는 인증된 WSS, Job별 내부 MCP는 공식 v2 SDK의 실제 Streamable HTTP를 사용한다. Bedrock은 Opus 설정을 읽고 SDK 자동 재시도를 끈다. 공유된 모델 게이트웨이가 승인된 합성 사이트 범위·입력 필터·Job 예산을 확인한다.

Extension은 사용자 툴바 동작에서 activeTab과 대상 탭을 고정한다. 패키지된 제한 해석기가 관찰/input/select/click/wait/navigation·사후 조건을 처리한다. 중복 Action 소비, 만료, 예상 이동과 임의 이동, Locator 없음/모호함, 민감 필드·frame/canvas 한계를 구분한다. Service Worker가 명령을 소유하고 페이지 메시지를 변경 확인으로 받지 않는다.

Keeper는 실제 API 상태로 자동 준비 진입, 채팅 초안 보존, 현재 대상, 작업/부분 준비/취소/미확인·변경 확인을 표시한다. Store 기본 화면은 실제 게시 목록을 조회한다. 개인 학습/설정·게시/설치·개선 화면은 후속 단계이며 완료로 표시하지 않는다.

검사: 8개 파일의 33개 테스트, typecheck/lint, 세 대상 빌드 통과. Repository 7, 업무 8, HTTPS/WSS 1, Extension 8, 생성/MCP 6, UI 2, 합성 범위 통합 1. MCP 검사는 실제 SDK 프로토콜이며 모델/브라우저 대역은 `tests/`의 명시된 합성 결과다. 새 사이트의 동일 준비 진입과 승인 범위 밖 모델 전송 차단을 검사했다.

## 진행 및 실제 증거

Step 1–10 구현·검사 완료. Step 11 진행 중. US-01~09/AC 전체 완료와 후속 단계 승인은 아직 아니다.

새 제품 로컬 TLS health를 WSL에서 인증서 검증과 함께 확인했다. Windows에서는 TrustFailure를 확인했고 사용자가 Chrome에 새 로컬 인증서를 신뢰 등록한 후 health 성공을 보고했다. Extension CORS credentials 응답과 툴바 기반 activeTab 취득을 수정하여 요청자의 기존 MinIO 탭과 실제 HTTPS 인증·WSS·관찰 연결을 확인했다. 다른 브라우저/관리자 세션이나 이전 probe를 대신 사용하지 않았다.

첫 새 제품 Opus 생성 요청: 모델 응답 수신, 요청 1회, 보고 usage 4,203 tokens, 브라우저 관찰 1회. 유효한 생성 후보 확정 전 중단되어 도구/Skill/실제 MCP 실행 성공은 아니다. 원시 응답은 로그/감사/Git에 저장하지 않았다. 구조화된 후보 반환 도구 스키마와 구분된 오류 처리를 보강해 후속 검증한다. 키 만료/잔여 크레딧은 미확인이다.

후속 실제 Opus 생성 2회(각각 5,213 / 5,420 tokens)에서 고정 후보를 생성하고 실제 MCP 호출이 기존 사용자 탭의 페이지 이동까지 이어졌다. 필수 라벨의 별표 처리와 문서 교체 타이밍 결함 때문에 업무 검증은 아직 실패다. 총 실제 모델 요청 3회/14,836 tokens이며 고정 후보를 다른 입력으로 재검증하는 경로를 추가해 실행기 수정 때 모델을 다시 부르지 않도록 했다. 완료된 변경은 자동 재실행하지 않고, 미확인 작업은 읽기 전용 상태 확인을 먼저 요구한다. 연결 성공과 업무 성공을 구분한다.

연결 수정 후 실제 Chrome에서 두 차례 재연결과 읽기 전용 사후 확인을 확인했다. 고정 후보 재검증은 모델 추가 호출 없이 실제 MCP를 통해 페이지 확인과 새 합성 값 입력까지 성공했다. 이어진 생성 버튼 클릭은 같은 텍스트의 제목/버튼 중복으로 ambiguous 판정되어 실행하지 않았다. 실제 클릭 가능한 요소만 해석하는 수정을 추가했고 중복 버튼 거절 회귀 검사를 포함해 27개 검사가 통과했다. 버킷 생성·기본 Skill 검증 완료로 기록하지 않는다. 입력한 합성 값은 현재 폼에 남아 있다.

### 첫 제품 전체 흐름 완료

현재 사용자가 선택한 demo Actor와 기존 로그인 탭에서 새 도구·기본 Skill을 각각 검증하고 같은 채팅에서 준비 자산을 재사용했다. 실제 생성된 합성 버킷은 `vibe-zoo-focus-tool-0909`, `vibe-zoo-final-skill-0909`, `vibe-zoo-chat-proof-0909` 세 개다. 채팅 실행은 실제 모델 2회·브라우저 동작 4회 뒤 사후 목록을 확인했다. 개인 Skill 학습·Store 설치·다른 브라우저 로그인 검증은 아직 아니다.

MinIO 입력의 focusin 수명과 비활성 버튼 검사를 수정했다. 최초 도구가 생성한 버킷은 남아 있었지만 후보의 결과 locator role이 실제 heading과 달랐다. 한 번의 제한된 모델 수정으로 불변 새 후보를 만들고 이미 실행된 사례를 읽기 전용으로 재평가했다. 기존 실패·unknown 영수증을 보존하며 생성 동작을 반복하지 않았다. 기본 Skill은 별도 새 입력으로 독립 검증했다. 수동 입력 진단은 제품 성공 증거에서 제외했다.

제품 실제 모델 호출 누계는 7회, 보고 usage 합계 25,731 tokens다. 상속된 Job 예산을 새 호출로 중복 계산하지 않았다. 기존 Haiku/Opus NFR probe와 별개이며 키 유효기간·잔여 크레딧은 미확인이다. 33개 회귀 검사는 unknown 보존·명시 미실행 검토·후보 검증 조건 약화 거절·독립 자산 검증·focusin/비활성 클릭을 포함한다.

[실제 생성·검증·채팅 화면](../../../../screenshots/01-generation-execution.png)은 Chrome 전체 화면에서 주소·자격 정보 없이 직접 캡처했다. 이미지 생성이나 결과 조작 없이 실제 MinIO 상태와 Keeper 응답을 보존했다.

### Record·개인 Skill 구현 진행

Step 11 코드: `src/extension/recorder.ts`, `src/extension/panel/learning.tsx`, `src/backend/generation/skills.ts`. 기존 관찰·제한 실행·MCP Validator와 Repository를 재사용한다. Record 동안 같은 대상의 자동 실행을 막고, Stop은 모델 호출 없이 의도 입력을 기다린다. 이벤트는 현재 Extension 메모리에만 두며 민감 필드/로그인 폼과 페이지가 합성한 이벤트를 제외한다. Stop 후 30분·취소·접수 확인 시 원시 버퍼를 버린다. 새 문서/다른 탭·출처로 넘어가 수집이 끊기면 재시연이 필요한 불완전 기록으로 처리한다.

명시적 의도와 최소 시연 근거로 초안을 한 번 생성하고 고정 도구 버전에 연결한다. 새 입력 보완은 같은 Job·후보·입력/제어 revision을 확인한다. 중복 접수는 기존 결과를 반환하며 완료한 검증은 재실행하지 않는다. 누락 원자 기능은 미준비 도구 후보/미지원 이유로 남긴다. 실제 개인 Skill 학습 검증은 아직 수행하지 않았으며 Step 11 체크박스를 열어둔다.

11개 파일 41개 테스트, typecheck/lint와 세 대상 build 통과. 새 합성 검사는 Record 슬롯·사용자/탭 경계, Stop에서 모델 미호출, 직접 의도 필요, 이벤트 필터/수명, 단일 컴파일·새 입력·revision/중복 보완과 미준비 후보, UI의 빈 의도 전송 금지를 확인했다. 원본 사례·성공 결과는 추가로 반복하지 않았다. 실제 학습 의도 답변을 기다리며 발표용 촬영/화면 다듬기는 전체 기능 완주 이후로 둔다.

Step 11 실제 완주: 기존 로그인 탭에서 Record 시작 후 `zoo-keeper-learn` 생성·Stop·의도 접수가 수행됐다. 직접 시연 변경은 학습 검증으로 재생하지 않았다. 실제 모델 1회/7,150 tokens로 개인 Skill 초안을 고정했고, 다른 입력 `vibe-zoo-personal-proof-0909`로 실제 MCP와 같은 대상 탭의 실행·사후 조건을 통과해 개인 자산을 활성화했다. 제품 모델 누계 8회/32,881 tokens. 원시 Record는 접수 확인 후 Extension 메모리에서 제거하며, 기존 도구/기본 Skill의 성공 검증을 반복하지 않았다.

Step 12 독립 코드와 합성 검사: Settings가 개인 이름/설명·typed 기본값·enabled를 CAS 저장한다. Registry는 off 자산/의존성을 신규 선택에서 제외하며 진행 중 스냅샷을 유지한다. MCP의 계약 검증 전에 해당 스냅샷의 기본값을 적용하고 명시 입력을 우선한다. 13개 파일 44개 테스트와 typecheck/lint 통과. 실제 기본값 후속 채팅은 진행 중이다.

Step 12 실제 완주: 개인 Skill의 이름을 ‘데모 버킷 만들기’로 저장하고 새 합성 버킷 이름을 개인 기본값으로 지정했다. 이름을 포함하지 않은 후속 채팅에서 해당 기본값으로 실제 개인 Skill이 실행되어 `vibe-zoo-default-proof-0909`를 생성하고 목록으로 확인했다. 모델 2회/4,866 tokens·브라우저 동작 4회, 제품 누계 10회/37,747 tokens. 코드 변경 전 성공 사례를 다시 검증한 것이 아니라 개인 기본값 기능의 새 입력 사례다. 실제 기록은 보존하고 후속 스크린샷 취합은 구현 우선 지시에 따라 Step 15로 모았다.

공유 경계 검토에서 변수 바인딩에 의해 덮어써지는 시연 인자가 Skill에 중복 저장된 것을 발견했다. 공개 투영과 모델 설명에는 이 사용되지 않는 인자를 제외하며, 실행의 ‘바인딩 우선’ 의미는 유지한다. 원본 불변 버전은 보존하고 공유 투영의 실제 인자 결과/개인 자료 제외를 합성 MCP 테스트로 확인한다.

### Step 13 — Store 게시·설치와 실제 증거 범위

검증한 개인 Skill을 Keeper 공개 미리보기와 명시 게시로 실제 공유했다. 고정 Skill/도구 2개이며 개인 기본값·원본 시연 입력·로그인 필드가 공개 투영에 없는 것을 확인했다. 실제 HTTPS에서 demo-keeper 인증·catalog 조회·개인 설치를 수행했고, 설치된 두 자산은 기본값 없이 미검증 상태를 유지한다. 모델/MinIO 변경 호출은 없다.

Store/repository/UI 11개 검사와 세 대상 빌드 통과. 기존 publication/installation을 보존하는 migration 2도 포함한다. Store 재로그인 시 이전 오류를 지우며 별도 창 제목을 Store로 구분했다.

사용자는 별도 Chrome 프로필 준비 불가로 독립 Store 시연만으로 구현 진행을 허용했다. 실제 Store 로그인 화면은 열었으나 UI 로그인·설치 완주는 확인하지 못했다(로컬 자동화 stdin 전달 문제 및 이후 창 부재). 위 설치 결과는 실제 API 증거다. 두 번째 사용자의 로그인 탭 실행은 보류하며 AC-07 전체 실제 검증으로 주장하지 않는다. Step 14 개선·Step 15 증거 취합·Step 16 전체 검토는 남아 있다.
