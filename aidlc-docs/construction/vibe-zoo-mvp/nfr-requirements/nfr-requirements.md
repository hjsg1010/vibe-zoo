- **상태**: 2026-09-09T01:15:35Z 명시적으로 승인된 NFR Requirements 산출물이다. 제품 구현·AC 충족·다음 단계 승인 완료를 뜻하지 않는다. 아래 보존기간과 작업 예산은 승인된 초기 설계 기준이며 실측에 따른 조정 조건을 유지한다.
- **기준선**: [스토리 CC-01~08](../../../inception/user-stories/stories.md), [BR-01~15](../functional-design/business-rules.md), [승인 Frontend](../functional-design/frontend-components.md), [최초 제약](../../../../requirements/constraints.md).

- **규모**: 1박 2일·5명 해커톤의 핵심 흐름 완주에 맞춘다. 참여자 수로 서버 용량·동시 사용자 수를 추정하지 않는다. 운영용 권한 체계·HA/DR·별도 부하 시험·상세 자원 벤치마크는 추가하지 않는다.

## 2. 사용자 결정의 적용

최신 답변과 변경 의도는 [NFR 계획 Q1~Q3](../../plans/vibe-zoo-mvp-nfr-requirements-plan.md)를 기준으로 한다.

- **Q1 변경**: 제품 기본 모델은 Amazon Bedrock Claude Opus 4.8이다. 생성·학습·채팅·Agent 호출은 Backend의 BEDROCK_MODEL_ID 설정을 사용한다. ANTHROPIC_MODEL의 [1m]을 API 모델 ID에 붙이거나 과거 모델로 자동 대체하지 않는다.
- **Q2**: 개발자 모드로 설치한 Chrome MV3 Side Panel Extension과 팀 공용 Backend를 사용한다. 일반 사용자가 CLI·하네스·Agent 앱을 직접 실행하지 않는다. Chrome Web Store 배포는 MVP 제외이며 Vibe Zoo 자산 Store는 별도 웹 화면으로 유지한다.
- **Q3**: 합성 업무 데이터로 구성한 MinIO 데모에서 필요한 최소 페이지 관찰·시연 근거만 민감정보를 제외한 뒤 글로벌 Bedrock으로 전송한다. 요청 리전 밖 처리 허용은 해당 합성 데모에 한정한다.
- **범위 보존**: 다른 미등록 사이트도 같은 생성 진입점을 제공한다. 해당 데이터의 전송 허용이 없으면 외부 모델 전송을 차단하고 이유와 다음 행동을 설명한다. MinIO 전용 생성기로 축소하거나 관리자 URL 사전 등록을 새 전제로 삼지 않는다.
- **검증 허용**: 사용자가 요청한 작은 전체 흐름 기술 검증만 이번 단계의 실행 예외로 적용한다. 이 요청을 산출물 승인이나 NFR Design·Infrastructure Design·Code Generation 진행 승인으로 해석하지 않는다.

## 4. 최소 신원·대상·데이터 경계

팀 운영자가 참여자별로 발급한 데모 자격정보를 Backend가 검증해 ActorContext를 구성한다. UI가 보낸 owner나 사용자 이름만으로 신원을 인정하지 않는다. 개인 대화·작업·자산·설정의 조회/수정과 Extension 연결을 이 신원에 결합하고 다른 참여자의 자격·소유권을 대신 사용하지 않는다. 발급·폐기와 잘못된 자격의 거절만 제공하며 조직용 계정 관리 체계를 추가하지 않는다.

Keeper와 Store는 같은 검증된 참여자 경계를 사용한다. 명시적으로 게시한 공유 버전만 공유 조회/설치 대상으로 노출하며, 개인 원본의 참조가 접근 권한이 되지 않는다. 설치는 실행 권한이나 로그인 상태를 전달하지 않으며 자신의 세션에서 검증한다(BR-01·12).

브라우저 작업마다 사용자·Extension 연결·탭·문서/페이지 상태·출처·Job·고정 버전과 제어 개정을 확인한다. Backend 확인에 더해 Extension이 실제 대상과 권한을 최종 확인한다. 기대한 페이지 이동과 사용자 임의 이동을 구분하고 다른 사이트에는 별도 대상 확인을 적용한다(BR-02). 관찰·변경 확인·입력 검증을 모델의 판단만으로 생략하지 않는다.

웹앱 로그인 세션과 인증정보는 사용자 브라우저에 남긴다. 모델 키는 Backend 설정으로만 주입하며 Extension·Store·자산·로그에 보내지 않는다. 비밀번호·토큰·쿠키·인증 헤더·브라우저 프로필과 그 값이 섞인 URL/입력은 수집·전송 전에 제외한다. 페이지 전체 DOM·영상 전체를 전송하지 않고 승인된 목적에 필요한 정제 신호만 선택한다. Backend에서도 저장·모델 입력·공유 직전에 허용 범위와 필드를 검증한다.

### 보존과 삭제의 초기 제안

별도 삭제 UI·계정 탈퇴 흐름·장기 보관 시스템은 만들지 않는다. 아래 정리는 최소 운영 명령과 실행 시 만료 확인으로 구현할 수 있으며 구체 저장 구조는 다음 설계에서 정한다.

| 데이터 | 보존 경계 | 삭제/검증 조건 |
|---|---|---|
| 민감 인증 입력·전체 DOM 덤프·전체 녹화 | 제품 저장소와 모델 입력에 보존하지 않음 | 합성 민감값이 수집·전송·로그·자산·공유에 없는지 확인 |
| 민감정보를 제외한 Record 원천 신호의 임시 버퍼 | Extension 메모리에서 수집하고 Stop 후 최대 30분. 필요한 개인 근거의 수신 확인 또는 취소 시 먼저 제거 | 만료/새로고침으로 소실되면 이유와 재시연 안내. 의도 입력 전 Stop만으로 실행·학습 확정하지 않음 |
| Backend의 수신 원문 버퍼 | 검증·정제하여 필요한 근거를 저장할 때까지만 메모리에 유지 | 처리 성공/실패/취소 후 제거하고 요청 본문을 로그에 남기지 않음 |
| 정제한 최소 개인 근거·검증 보고 | 소유자·Record/Job·후보/자산 버전·검증 사례에 연결. 생성 전에도 개인 범위로 유지 | 개인 데이터 정리 시 함께 제거. 공유 자산은 이 개인 근거에 접근해야만 사용할 수 있는 구조로 만들지 않음 |
| 개인 대화·작업·자산/버전·설정 | 새로고침·재접속과 데모 재현을 위해 지속 저장 | 데모 종료 후 7일 이내 팀 정리. 그 전 요청된 개인 정리는 해당 소유자 범위로 처리 |
| 명시적으로 게시한 버전·공개 의존성·정제 요약 | 개인 원본과 분리한 공유 스냅샷으로 보존 | 개인 삭제가 이미 공유한 버전이나 타인의 설치본을 암묵적으로 삭제하지 않음. 데모 전체 정리 시 공유 자료도 별도로 제거 |

개인 정리 시 진행 중 Job을 먼저 중단하고 새 접근을 차단한 뒤 연결된 개인 상태·근거를 제거한다. 늦은 응답이 삭제된 데이터를 다시 생성하지 않도록 BR-08의 취소/개정 경계를 적용한다. 단순 정리 확인으로 충분하며 복구 백업·법적 보존·운영 감사 체계를 추가하지 않는다. 공개 스크린샷과 README는 합성 자료만 별도로 선별한다.

## 5. 작업 일관성과 초기 예산

대화·장기 Job·Extension 연결의 수명은 분리한다. 새로고침과 연결 복구 후 저장 상태를 조회하되, 새 연결만으로 실행 재개를 결정하지 않는다. 이미 전달한 변경은 실제 결과를 먼저 확인하고 미확인 상태에서는 자동 반복하지 않는다. 중복 요청은 기존 Job/결과에 연결한다(BR-03·08~09).

취소 이후 새 모델·탐색·변경 명령과 자동 활성화를 중단한다. 이미 전달한 동작의 결과 확인만 BR-08의 제한된 읽기 관찰로 허용하며 대상·권한을 다시 확인한다. 결과가 끝내 불명확하면 부분 완료·결과 확인 실패를 그대로 표시한다. 취소나 버전 롤백이 웹앱의 기존 변경을 되돌렸다고 표현하지 않는다.

실행 중인 버전·설정·입력은 고정한다. 개선 후보는 실패 사례와 관련 성공 사례의 검증 후에도 현재 버전과 분리하며, 사용자의 명시적 적용과 개정 확인을 거쳐 향후 Job에 사용한다. 초기 생성·기본/개인 Skill 준비에 개선용 적용 gate를 추가하지 않는다(BR-04·07·13~14).

다음 값은 소규모 데모의 출발점이며 SLO·응답 시간 보장·비용 보장이 아니다. 첫 실제 흐름에서 부족한 근거와 종료 사유를 확인해 조정하고 변경값·조건은 기술 결정 문서에 기록한다.

| 예산 | 초기 설정 예시 | 적용 방식 |
|---|---|---|
| Job의 능동 처리 시간 | 300초 | 모델/탐색/검증 처리 합계. 사용자 확인·입력·재접속 대기에는 새 작업을 보내지 않으며 처리 시간은 초기화하지 않음 |
| 브라우저 작업 | Job당 총 60회 | 관찰·실행·검증을 합산하고 최대 5회는 이미 전달한 동작의 읽기 결과 확인에 예약. 남은 예산 없이 변경을 추가하지 않음 |
| 모델 호출 | Job당 최대 8회, 응답당 최대 4,096 출력 토큰 | 생성·검증 제안·도구 결과 왕복·재시도를 함께 계산하고 모델별 적용 가능성은 기술 문서에서 검증 |
| 누적 모델 토큰 | Job당 입력+출력 60,000 토큰 기준 | 호출 전 입력 추정치와 최대 출력을 예약하고 실제 usage로 보정. 예약/실측 합계가 상한을 넘으면 다음 호출 차단하며 추정치로 정확한 비용 상한을 보장하지 않음 |
| 자동 재시도 | 논리 요청당 추가 1회 이내 | 일시적 모델/통신 오류만 전체 예산 안에서 허용. 인증·권한·입력 오류는 자동 반복하지 않고 웹앱 변경은 BR-09 확인 전 재전송하지 않음 |

각 상한은 먼저 도달한 조건으로 새 작업을 멈추며 모델 호출 내부 재시도도 합산한다. 사용자 입력 보완·중복 요청·재접속으로 예산을 리셋하지 않는다. 취소된 작업의 새 요청은 BR-08에 따른 별도 연결 Job이며 자동 반복으로 만들지 않는다. 한도에 도달한 미완성 결과는 실행 가능/성공으로 승격하지 않는다.

준비된 자산을 우선 재사용하고 현재 사이트·요청에 필요한 도구/Skill만 모델에 제공한다. 긴 생성이 일반 채팅과 기존 자산 사용을 계속 막지 않도록 대기와 처리를 분리하되, 같은 탭의 충돌하는 관찰/변경은 BR-03에 따라 조정한다. 대표 흐름의 대기 시간·실제 토큰·작업 수·정제된 종료 사유만 확인한다.

## 6. 사용자 안내와 지원 범위

승인된 Frontend의 채팅·도구·내 Skill·설정 명칭과 사육사/훈련사 표현을 유지한다. Extension 작업의 로딩·빈 상태·현재 대상·변경 확인·후속 행동은 같은 Panel에서, 공유/설치 결과는 Store 웹 화면에서 보여준다. 일반 사용자에게 서버 원문 오류·내부 경로·모델 인증정보를 표시하지 않는다.

Record는 표시된 대상 범위에서 수집하고 Stop 후 해당 기록에 사용자의 의도를 연결한다. 기존 학습 Job의 검증 입력 보완은 고정 후보와 입력 개정을 이어받으며 새 컴파일이나 이미 수행한 변경 재실행으로 바꾸지 않는다(BR-10). 로그인 만료·권한 부족·단절·지원 불가와 부분 완료·결과 확인 실패의 이유와 다음 행동을 구분한다.

SPA와 탭/문서 수명, 동일/교차 출처 및 접근 불가 iframe, 표준/비표준·Canvas·접근성 부족 UI, Chrome 내부 페이지, 로그인/권한별 화면과 목록/상세/빈 상태를 실제 관찰 대상 목록으로 유지한다. 이 목록 전체의 지원 구현을 약속하지 않으며 확인하지 않은 페이지 종류를 지원으로 표시하지 않는다.

현재 사용자 브라우저와 실제 로그인 세션이 검증 대상이다. 자동화 도구가 연 별도 브라우저를 해당 세션의 증거로 대체하지 않는다. 실제 연결·최소 Chrome 버전·프레임/권한·MV3 어댑터 표현의 검증 현황은 기술 문서를 단일 원본으로 사용한다.

## 7. 최소 품질·증거와 승인 경계

의존성 선언·락파일·진입점·실행 명령과 간단한 CI를 제공한다. 모듈 책임·설정/시크릿 분리·주요 예외와 전역 오류 처리·간단한 실행/오류 로그를 갖추고 핵심 흐름을 빈 함수·TODO·모의 성공으로 남기지 않는다. 로그는 정제된 작업 종류·상태·소요 시간·오류 분류 정도로 제한하고 실제 주소·원문·인증값·런타임 식별자를 공개 기록하지 않는다.

검증은 기존 AC-01~10과 CC/BR에 연결한다. 실제 MCP 검색/호출에서 요청자 탭의 사후 상태까지, 다른 입력 실행, 설정 유지, 다른 참여자 설치와 자신의 세션 검증, 개선의 실패/관련 성공 재검증 및 명시적 적용을 확인한다. 잘못된 사용자/탭/문서·취소 경합·단절 후 미확인 변경·전송/개인/공유 분리도 핵심 확인 대상이다.

실제 제품 스크린샷은 루트 screenshots/ 또는 result/에 두고 README의 구현 기능·설정 변수명·실행 순서·지원 한계·문제 해결과 일치시킨다. 합성 데이터를 사용하며 시안·타이머·고정 응답을 실행 증거로 삼지 않는다. 지연·효율 개선 수치를 제시할 때만 실제 측정 조건과 표본을 함께 남긴다.
