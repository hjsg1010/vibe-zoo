# U-01 — Logical Components

## 1. 구성과 경계

**상태**: 2026-09-09T01:27:56Z NFR Design 사용자 승인 완료. 제품 구현 전. [NFR 패턴 P-01~07](nfr-design-patterns.md)을 기존 [C-01~07](../../../inception/application-design/components.md)에 배치한다. 이 문서는 서버 수·테이블 전체 스키마·REST 경로를 추가 확정하지 않는다. 승인된 초기 구성은 Chrome MV3 Extension, Store 웹 화면, 역할별 모듈을 가진 Node.js Backend 하나와 같은 서버의 지속 SQLite다.

브라우저 작업은 요청자의 기존 탭에서만 수행한다. 공용 Backend에 대체 로그인 브라우저를 두지 않는다. HTTP/WSS의 공용 주소·TLS 종료·서버 자원·DB 드라이버 버전은 Infrastructure Design에서 실제 환경에 연결한다. 제품 코드·추가 모델 호출·배포를 이 설계 단계에서 수행하지 않는다.

## 3. 저장·연결·호출 계약

### 지속 데이터와 일시 데이터

| 위치 | 저장하는 정보 | 복구/정리 기준 |
|---|---|---|
| Backend 비공개 설정 | AWS_BEARER_TOKEN_BEDROCK, AWS_REGION, BEDROCK_MODEL_ID 및 서버 설정 | 루트 .env 또는 같은 이름의 서버 환경변수. 값 미출력·Git 제외, ANTHROPIC_MODEL은 제품 모델 입력이 아님. |
| SQLite — C-03 소유 | Actor 자격/세션의 검증값·사용 가능 상태, 대화, Job 스냅샷/예산/control revision, 중복 접수, Action 의도/receipt/관찰 참조, 고정 변경 확인 | 재접속 후 조회 기준. 비공개 런타임 참조를 공개 로그로 내보내지 않음. 취소/전달/결과 경계는 P-02·03. |
| SQLite — C-06 소유 | 불변 자산/의존 버전, 개인 설정/포인터와 본인 검증, 최소 개인 근거, 공개 스냅샷·설치 관계 | owner와 revision을 조건에 포함. 게시/설치/포인터 전환은 서로 다른 효과이며 개인 삭제가 공유본을 암묵적으로 제거하지 않음. |
| Backend 메모리 | live socket·단기 실행 문맥 참조·Job 제어 순서·대상 슬롯·모델 진행 요청 | 재시작 시 소실을 전제. DB의 과거 binding으로 live 권한을 복구하지 않음. |
| Extension session 저장소 | Vibe Zoo 세션 자격, 최소 접수/소비 참조와 화면 복구 힌트 | 신뢰된 확장 컨텍스트 전용. 복원된 참조는 실행 허가가 아니며 현재 대상/Backend 상태를 재확인. |
| Extension 메모리 | 필터된 Record 버퍼·현재 문서 관찰 | Stop 후 보존/수신 확인/취소·소실은 승인 NFR 표 적용. 원본 녹화·인증 입력 저장 없음. |

SQLite는 WAL과 짧은 쓰기 구간으로 시작한다. 메모리 큐는 재생 가능한 명령 목록이 아니라 현재 실행 순서이며, 재시작 후에는 Job/Action 상태를 재평가한다. 페이지화된 owner별 조회와 중복 키·자산 버전·현재 작업 조회에 필요한 인덱스만 둔다. 실제 DDL과 migration은 Code Generation 계획에서 작성하고 로컬 디스크 요구는 Infrastructure Design에서 확인한다.

### 연결과 입력 검증

- **HTTPS**: 설정/조회/작업 접수·확인·취소·게시/설치를 C-03에서 인증/검증한다. 명시적 변경에는 중복 키와 필요한 expectedRevision을 붙인다. 입력 보완은 기존 Job·고정 후보·입력 revision을 함께 보낸다.
- **WSS**: 인증된 Extension 연결의 hello/bind, control, operation/receipt, observation, 진행 알림을 구분한다. 수신한 종류·크기·스키마·실행 문맥을 검사한다. 초기 메시지 크기 상한은 256 KiB로 두며 큰 관찰/Record는 목적별 최소 신호로 줄이거나 기록 부족으로 표시한다. 원문을 무한 버퍼링하거나 조용히 잘라 완전한 근거로 취급하지 않는다.
- **MCP**: 실제 SDK 검색·호출은 내부 접근으로 제한한다. 공개 브라우저 연결과 같은 의미의 엔드포인트가 아니다. C-03의 인증된 실행 문맥과 C-05의 고정 버전 레지스트리를 연결하고 모델 입력의 실행 대상/권한 필드를 받지 않는다. 검증 후보는 해당 Job 문맥 밖에 노출하지 않는다.
- **모델**: Gateway에서 예산을 예약한 후 Converse를 호출한다. 잘못된 스키마·알 수 없는 도구·여러 도구 호출은 검증하고 동일 탭에 병렬 전달하지 않는다. 잘린 생성 응답은 완성 자산이 아니며 남은 예산 안에서 명시적으로 보완하거나 후보/미준비로 반환한다.
- **연결 오류**: 일시적 연결/논리 요청은 승인 NFR의 추가 1회 한도와 짧은 backoff를 적용한다. HTTP 재전송은 같은 중복 키를 쓰며 브라우저 Action은 자동 재전달하지 않는다. 계속 실패하면 연결 복구/재요청을 안내한다. 인증 실패는 재시도하지 않는다.

Extension 설치 패키지에는 Backend/Store 접속 설정과 필요한 브라우저 권한만 포함한다. Bedrock 키와 참여자 자격을 번들에 넣지 않는다. 대상 사이트 권한은 현재 사용자가 확인한 탭에서 확보하며 원격 코드나 모든 브라우저 프로필 접근을 요구하지 않는다. 미등록 사이트도 같은 prepare/generate 진입점을 사용하고 모델 전송 허용 범위는 별도 정책으로 검사한다. 합성 MinIO의 비공개 주소를 제품 코드에 고정하지 않는다.

## 4. 대표 실행의 모듈 연결

다음 연결은 [승인 기능 흐름](../functional-design/business-logic-model.md)을 구현하는 공통 경로다. 개별 UI 단계와 수용조건을 다시 정의하지 않는다.

1. C-01이 C-02에서 현재 대상을 얻어 C-03에 요청한다. C-03은 인증·입력·중복을 검사하고 JobReceipt를 먼저 반환한다. 기존 C-06 자산을 찾고 필요한 버전·개인 설정/입력·제어/예산을 고정한다.
2. 생성/학습/개선이면 C-03이 정제 근거를 C-04에 전달한다. C-04는 공유 ModelGateway를 통해 후보를 제안한다. C-03/C-06이 도구 여섯 요소 또는 Skill의 절차/의존 버전을 고정한다. 입력 보완·변경 확인은 Job을 대기시키며 모델 슬롯을 놓는다.
3. C-03이 C-05의 실제 MCP 검색/호출 또는 후보 제한 검증을 요청한다. P-02의 현재 제어 판정 후 C-03 BridgeGateway가 C-02에 한정된 동작을 전달한다. C-02는 마지막으로 대상·문서·권한·만료/소비 상태를 검사한다.
4. C-02가 동작 receipt와 사후 관찰을 반환하고 C-05가 기대 조건과 비교한다. C-03은 정제한 실제 결과를 모델에 연결하고 다음 단계 전 현재 제어/예산을 재검사한다. 이미 실행한 Skill 동작을 검증 때문에 반복하지 않는다.
5. C-03/C-06은 근거 저장과 개인 준비/포인터 반영을 구분한다. 최초 생성·개인 Skill·설치는 본인 검증을 통과하면 기존 사용 흐름으로, 개선은 통과 후보를 표시한 뒤 사용자가 적용한 경우에만 현재 포인터를 바꾼다. 어느 경로도 자동 게시하지 않는다.
6. C-01 또는 C-07은 해당 Job/자산 revision의 저장된 상태를 조회·표시한다. 취소·단절·예산 도달은 실제 완료 부분과 미확인 부분을 분리해 보여준다.
