# U-01 — Business Rules

**상태**: 2026-09-08T11:39:23Z Functional Design 사용자 승인 완료. 상태·엔터티의 원본은 [domain-entities.md](domain-entities.md), 기능별 순서는 [business-logic-model.md](business-logic-model.md)다. 아래 BR은 [CC-01~08](../../../inception/user-stories/stories.md)의 구현 판단을 상세화한다. 공통 수용조건 전문과 기술 선택은 반복하지 않는다.

## BR-01 — 사용자와 실행 허용

C-03은 확인된 ActorContext로 대화·작업·설정·근거의 소유권과 공유 접근권을 검사한다. UI가 보낸 owner·대상 선택만 신뢰하지 않는다. 일반 MCP 검색·실행 선택은 본인의 사용 버전, 준비된 의존성, 개인 enabled와 적용 범위를 만족해야 한다. 선택된 자산·의존 도구의 설정은 BR-04의 Job 스냅샷을 따르되 현재 권한·대상·취소 제어는 매 동작 확인한다. 검증 모드는 지정 후보·사례·Job에만 한정하여 미검증 도구를 실행할 수 있으며 일반 검색에 그 후보를 노출하지 않는다. C-02도 관찰·실행 직전에 현재 제어·권한·대상을 확인한다. 브라우저가 필요 없는 설정·Store 조회에 활성 탭을 강제하지 않는다. (CC-01, FR-04·07)

## BR-02 — 대상과 정상 이동

동작은 사용자·Extension 연결·탭·문서/페이지 체크포인트·출처·Job·고정 버전에 연결한다. 허용된 동작이 예상한 SPA 상태 또는 문서 이동을 만들면 receipt와 새 관찰로 그 이동의 일치를 확인하고, 같은 사용자·연결·탭·허용 출처의 다음 체크포인트를 새 binding revision으로 연결한다. 다음 동작은 새 문서에서 제어를 다시 검사하며 이전 동작의 허가를 전용하지 않는다.

사용자의 임의 이동, 설명되지 않은 문서 변경, 다른 탭·출처, 접근 불가 프레임은 실행을 멈추고 재확인한다. 허용된 이동처럼 추정하여 흡수하지 않는다. 다른 사이트 업무가 필요하면 그 탭의 연결·권한과 변경을 별도로 확인한다. 페이지 이름·마지막 활성 탭·같은 URL만으로 동일 실행 대상임을 판단하지 않는다. (CC-01·06, NFR-06)

## BR-03 — 접수 중복과 탐색 한도

같은 사용자의 동일 요청 재전송은 기존 JobReceipt를 반환한다. 자동 생성은 owner·사이트 적용 범위·생성 목적에 연결된 진행 작업을 먼저 찾으며 문서 이동마다 새로 만들지 않는다. 기존 작업을 다른 탭에 옮기는 대신 그 진행을 보여주고 원래 대상의 재확인을 기다린다. 다른 사용자의 같은 사이트 작업·근거를 재사용하지 않는다.

호환 자산을 먼저 재사용하고 부족한 범위만 관찰한다. 시간·행동·토큰·재시도 예산을 Job과 시도 이력에 연결하며 자동 재시도로 초기화하지 않는다. 상한·취소를 추가 관찰/모델 호출/실행 전에 검사하고 도달 사유와 준비된 범위를 반환한다. 일반 채팅과 준비된 자산 사용은 긴 생성과 독립 진행할 수 있다. 같은 탭에서 충돌하는 관찰·변경은 대상 체크포인트로 조정하며 서로의 화면을 조용히 바꾸지 않는다. 구체적 한도·동시성 기술은 NFR 단계에서 정한다. (CC-06·08)

## BR-04 — 입력과 실행 스냅샷

선택한 자산 및 의존 버전과 개인 설정 revision을 고정하고, 명시 입력 → 개인 기본값 → 해당 버전의 기본값 순서로 실제 입력을 결정한다. 필수값 누락·타입·허용 범위·알 수 없는 키·단계 연결 오류는 계약으로 검사하여 해당 항목을 설명하고 실행하지 않는다. 특정 사이트 규칙을 모든 사이트에 적용하지 않는다.

후속 단계의 입력이 앞 단계 결과에 의존하면 결과를 관찰한 뒤 확정하고, 그 실제 입력에 변경 확인을 연결한다. 사용자의 새 설정·최신 공유 버전이 진행 중 입력이나 의존 버전을 바꾸지 않는다. 계약/절차/어댑터/성공 조건/의존 버전의 변경은 새 후보로 검증하며 이름·설명·유효한 개인 기본값 편집만으로 실행 자산을 덮어쓰지 않는다. (CC-01·03·06, FR-06)

## BR-05 — 변경 확인 범위

탐색·후보 검증·학습 후 검증·업무 실행 모두 실제 변경 전에 대상·변경 내용·확정 입력을 제시한다. 확인은 Job·후보/사용 버전·binding revision과 표시된 동작 또는 한정된 묶음에 연결한다. 확인 거절·취소·대상/입력/범위 변경은 그 제안의 실행을 막는다. 묶음에 포함되지 않은 다음 변경은 새 확인 대상이다. 응답을 중복 전달해도 같은 동작을 새로 실행하지 않는다.

Record 시작/Stop, 채팅 전송, 자산 on, 개선 ‘적용’은 임의 웹앱 변경의 포괄적 확인이 아니다. 직접 시연에서 이미 수행한 변경은 기록으로 다루며 학습 요청만으로 같은 변경을 재생하지 않는다. (CC-03·04)

## BR-06 — 검증과 업무 성공

ValidationCase는 실행 전에 대상 버전·입력·기대 사후 조건·목적을 가진다. C-05는 실제 MCP 호출, 그 사용자의 브라우저 동작, 실행 뒤 업무 상태 관찰을 연결해 판정한다. 클릭·응답 성공·생성 모델의 설명만으로 통과하지 않는다. 예상 상태를 관찰할 수 없으면 미확인, 관찰된 상태가 기대와 다르면 실패다. 이미 끝난 Skill 동작은 기존 실행 참조와 사후 관찰을 묶어 평가하며 validate 때문에 반복하지 않는다.

도구·개인 Skill은 관찰/시연과 다른 유효한 입력을 실행해 해당 입력에 맞는 사후 상태를 확인한다. 판별 가능한 새 입력이나 관찰 근거가 없으면 검증 부족으로 남긴다. 통과는 검증한 기능·owner·자산/의존 버전·적용 범위에 한정한다. 새 실행의 현재 권한 확인을 면제하거나 전 사이트 지원으로 확대하지 않는다. (CC-01~03, AC-02~04)

## BR-07 — 부분 준비와 결과 반영

C-06은 도구 후보의 ToolBundle 여섯 요소 연결, Skill 후보의 절차·변수·기본값·성공 조건·고정 의존 버전을 자산 종류에 맞게 검사하고 해당 버전·범위의 유효한 보고서로 준비 상태를 반영한다. 도구 일부가 먼저 통과하면 해당 기능부터 사용할 수 있다. 기본/개인 Skill은 자신의 절차·의존 도구·전체 사후 조건 검증이 필요하며 도구 한 개의 통과를 상속하여 준비되지 않는다. 나머지 후보·미지원·미확인 이유는 보존한다. personal enabled만 바꾸어 검증을 승격하지 않는다.

최초 생성·개인 Skill 검증·선택 버전 설치의 사용 가능 전환은 승인된 흐름에서 수행하며 별도 개선 ‘적용’ 확인을 신설하지 않는다. 개인 사용 흐름의 최초 설정을 만들되 이미 저장한 off는 유지한다. 현재 버전을 대체하는 개선은 BR-13을 따른다. 어느 경우든 생성·저장·활성은 게시를 동반하지 않는다. (FR-02·03·05·07, CC-02·06)

## BR-08 — 취소와 반영 경합

취소 사실은 단조롭게 기록하고 원작업을 계속하는 모델 호출·추가 탐색·브라우저 동작 전달과 자동 활성화를 막는다. 예외는 이미 전달된 특정 ActionExecution의 결과를 확인하는 **변경 없는 제한 관찰**이다. C-03 controlJob(reconcile)은 현재 대상·권한을 다시 확인하고 그 동작·사후 조건에만 한정된 관찰 목적을 ExecutionControl에 연결한다. C-02 inspect/observe도 그 목적과 범위를 검사한다. 이 경로는 새 변경·탐색 재개·후보 활성화 권한을 주지 않는다.

전달 직전과 결과 반영 시 캐시된 JobContext 대신 현재 제어 revision을 검사한다. **취소와 실행 허용/자산 반영의 판정 순서는 분리된 확인 후 무조건 저장으로 구현할 수 없다.** 제어 유효성·대상/후보/검증·현재 버전 조건을 확인하고 반영하는 경계에서 오래된 요청을 배제해야 한다. 구체적 원자성 수단은 NFR Design에서 정한다.

취소 전에 이미 전달한 동작은 진행되었을 수 있으므로 실제 결과를 확인한다. 확정된 변경·이전 활성화·명시 게시를 취소가 되돌렸다고 하지 않는다. 늦은 근거는 취소 출처를 붙여 보존할 수 있지만 자동 활성화하지 않는다. 취소한 Job의 제어를 다시 여는 대신, 재요청은 BR-09 판정 후 새 연결 Job으로 받는다. 보존 후보를 다시 검증하려면 새 유효 작업·검증이 필요하다. 원작업 취소가 별도 기존 검증 자산에 대한 새 명시 게시를 영구 금지하는 것은 아니다. (CC-04·06)

## BR-09 — 재접속과 미확인 변경

재연결은 대화·작업·자산을 조회한 뒤 현재 사용자·대상·권한을 다시 확인한다. 전달된 변경의 응답이 없으면 같은 ActionExecution의 의도·실제 입력과 사후 상태를 대조한다. 관찰만으로 기존 결과를 확인할 수 있는 경우 실행을 반복하지 않는다.

| 확인 결과 | 허용되는 다음 행동 |
|---|---|
| 해당 변경 수행과 결과가 확인됨 | 완료한 단계를 건너뛰고 결과를 갱신한다. 남은 단계는 현재 제어와 필요한 변경 확인 후 재개한다. |
| 해당 변경이 미실행임을 확인할 충분한 근거가 있음 | 재요청·유효 대상·필요한 확인을 거쳐 그 단계의 새 시도를 허용한다. |
| 수행 여부 또는 업무 결과를 확정할 수 없음 | 미확인 상태와 이미 아는 결과를 표시한다. 자동 반복하지 않고 추가 관찰/사용자 확인 경로를 제공한다. 사용자 주장만으로 관찰하지 못한 성공을 꾸미지 않는다. |

응답 없음·일시적 목록 부재만으로 미실행을 단정하지 않는다. 연결 복구만으로 취소를 해제하거나 다른 현재 활성 탭으로 기존 작업을 옮기지 않는다. (CC-01·02·04~06)

## BR-10 — 기록과 명시적 의도

Record는 현재 확인된 대상·수집 범위를 표시하고 시작한다. 사용자가 같은 확인된 탭·허용 출처 안에서 여러 페이지를 시연하면 관찰 가능한 이동을 기록하고 새 문서의 관찰 범위·연결을 다시 확인한다. 이는 자동 실행 중 예상 밖 이동을 다루는 BR-02와 구분한다. 범위 밖 탭/출처·접근 불가 영역·단절이면 기록을 멈추고 부족한 범위를 남긴다.

Stop 후 해당 기록에 사용자가 직접 입력한 비어 있지 않은 의도를 연결해야 학습을 접수한다. 특정 업무 완료를 Stop 조건으로 고정하지 않는다. 충분한 기록 근거가 없으면 재시연을 안내한다. 의도/기록 revision과 학습 Job을 묶어 이전 시연의 늦은 초안이 새 시연을 덮어쓰지 않게 한다. 기존 도구를 우선 조합하고 누락된 원자 기능은 생성 후보/미지원으로 남긴다. (FR-05, CC-06·07)

초안 후 검증 입력이 더 필요하면 학습 Job을 입력 대기로 둔다. startWorkflow(learning)의 보완 입력은 **기존 Job + 고정 후보 버전 + 기대 입력 revision**을 식별하여 대기 중인 같은 검증을 이어간다. 새 최초 접수와 구분하고 재학습·재컴파일·이미 완료한 변경 재실행을 만들지 않는다. 오래된 후보/revision, 취소·종료한 Job의 보완은 거절하며 중복 보완은 기존 접수 결과를 반환한다. 후보 내용 변경이나 실패 후 재요청은 이 보완 경로가 아니라 BR-04/09의 새 후보·시도 규칙을 따른다.

## BR-11 — 개인 설정과 수정 충돌

이름·설명은 의미 있는 비어 있지 않은 문자열, 기본값은 해당 계약, enabled는 명시적 on/off로 검증한다. C-06은 expectedRevision으로 최신 편집을 덮어쓰지 않으며 충돌 시 최신값과 사용자의 미저장값을 구분해 다시 편집하게 한다. 저장 완료 후 조회한 값이 새로고침·다음 채팅의 기준이다. 개인 편집은 공유 원본·다른 설치자 설정에 영향을 주지 않는다. off한 자산은 새 실행 선택에서 제외하되 취소와 혼동하여 이미 시작한 Job의 버전·입력을 변경하지 않는다. (FR-06, CC-06)

## BR-12 — 선택 버전 공유와 자체 설치 검증

게시는 사용자가 선택한 특정 버전과 공개할 항목의 명시적 요청으로만 수행한다. 자산 설명·작성자·적용 범위·의존 버전·검증 범위와 한계를 표시한다. 공개 불가 자료가 섞이면 제거/수정을 안내하고 그 자료를 게시하지 않는다. 공유된 참조만으로 개인 기록에 접근할 수 없어야 한다.

설치는 선택 버전과 필요한 의존 버전을 설치자 개인 영역에 연결한다. 이용할 수 없는 의존성은 이유와 함께 미준비로 남긴다. 동일 설치 요청의 재전송은 중복 자산을 만들거나 기존 개인 설정을 초기화하지 않는다. 설치자 자신의 사용자·로그인된 탭·고정 버전·의존성에서 검증해야 일반 실행 준비가 된다. 공유자 검증은 참고 근거이며 설치자 권한·자체 검증을 대신하지 않는다. 새 공유 버전을 자동으로 따라가지 않는다. (FR-07, CC-01·02·07)

## BR-13 — 개선 검증과 명시적 적용

[Question 1의 A 승인](../../plans/vibe-zoo-mvp-functional-design-plan.md)에 따른다. 기준 현재 버전과 재현 실패·관련 성공 사례에서 변경 이유가 있는 후보를 만든다. 사용자 수정·추가 시연은 선택적 보조 근거다. 후보는 해당 실패 해결과 관련 성공 사례 유지가 모두 관찰되어야 적용 가능하다. 실패·미확인·취소면 현재 버전을 유지한다.

통과해도 현재 버전은 유지하고 후보·이유·검증 범위를 보여준다. 사용자가 본 **특정 후보 + 유효 보고서 + 기준 현재 버전**으로 ‘적용’을 요청하면 C-03/C-06이 권한·취소 여부·검증/의존성 일치·expectedCurrent를 확인하여 현재 포인터와 이전 버전 연결을 함께 반영한다. 그 사이 현재 버전이 달라졌으면 최신 상태와 충돌 이유를 반환하며 자동 덮어쓰기/재적용하지 않는다. 확인받은 요약의 검증 조건이 달라져도 다시 평가한다.

적용은 이후 Job의 기본 버전만 바꾸고 진행 중 고정 버전·개인 on/off·기존 공유 버전을 바꾸지 않는다. 같은 적용 요청의 응답 유실 후에는 반영 여부를 조회하여 중복 전환하지 않는다. BR-08의 제어/반영 경계가 적용되며 검증 통과를 취소된 원작업의 소생 근거로 쓰지 않는다. (FR-08, AC-08, CC-04~06)

## BR-14 — 이전 버전 복구

사용자가 보존한 이전 버전을 선택하면 소유권·버전/의존성·검증 범위·expectedCurrent를 확인해 이후 업무의 사용 포인터를 전환한다. 호환성이나 근거가 부족하면 복구 선택과 현재 실행 준비를 구분하고 재검증을 안내한다. 진행 중 버전은 고정하며 개인 설정을 임의 초기화하지 않는다. 웹앱에서 발생한 변경을 되돌리는 보상 실행은 이 기능에 포함하지 않는다. (FR-08, CC-02·06)

## BR-15 — 결과 전달과 데이터 경계

작업 접수·진행·확인 요청·결과는 원래 대화/화면과 Job에 연결한다. 오래된 응답으로 최신 상태를 덮어쓰지 않는다. 사후 상태 근거, 실제 발생한 변경, 남은/미확인 범위, 중단 이유와 다음 행동을 WorkOutcome으로 반환한다. 진행 중이라는 이유만으로 숫자형 성공률·완료를 만들어 표시하지 않는다. 미지원은 관찰 가능한 범위와 이유를 가진다.

C-02는 필요한 관찰·기록에서 민감 입력을 제외한 뒤 C-03/C-04에 전달한다. 자산·공개 요약에 인증정보·브라우저 프로필·원본 시연·개인 대화를 복사하지 않는다. 개인 기본값도 게시 요청만으로 공개 데이터가 되지 않는다. 전송/저장/삭제 세부 경계와 보존 정책은 NFR 단계에서 정하며 공개 예시·로그는 합성 자료를 사용한다. (CC-02·07, NFR-02·05·08)
