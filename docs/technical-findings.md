# Vibe Zoo 사전 기술 관찰 요약

이 문서는 이전 검토에서 얻은 기술적 교훈을 공개 가능한 형태로 요약한다. 원본 로그인 정보, 실제 접속 주소, 내부 실행 기록과 브라우저 식별자는 포함하지 않는다.

## 확인한 내용

- 로그인된 사용자 브라우저에서 MinIO 화면을 읽고, 버킷 생성·조회·정리 절차를 수행할 수 있었다.
- 서로 다른 버킷 이름으로 작업하고 새 목록 조회로 결과를 확인했다.
- 같은 요청도 인증된 브라우저와 인증되지 않은 별도 HTTP 환경에서 다른 결과를 보였다. Backend의 새 브라우저가 사용자의 로그인 상태를 자동으로 갖는다고 볼 수 없다.
- 없는 자원에 대한 일부 응답이 HTTP 200이어도 실제 목록에는 없었다. 상태 코드만으로 성공을 확정하면 안 된다.
- 빈 화면과 관리 목록에서 같은 기능으로 진입하는 버튼의 이름과 위치가 달랐다. 하나의 선택자와 시연 값만 저장하는 방식은 충분하지 않다.
- 해당 관찰 환경에는 사이트가 제공하는 Native WebMCP가 없었다.

## 아직 증명하지 않은 내용

이 관찰은 완성된 자동 생성기를 평가한 결과가 아니다. 임의 사이트 자동 탐색, 코드/어댑터 자동 생성, 실제 MCP 서버 전체 연결, 다중 사용자 라우팅과 개선 루프는 새 프로젝트에서 구현·검증해야 한다.

[사용자 경험 시안](../prototypes/vibe-zoo-experience/index.html)과 [구조 시안](../prototypes/vibe-zoo-experience/architecture.html) 역시 클릭 가능한 모의 자료다. 실제 웹앱, LLM, MCP 서버와 연결되지 않는다.

따라서 초기 기술검증은 **실제 페이지 관찰 → 새 도구 생성 → MCP 검색·호출 → 같은 사용자 탭에서 다른 입력으로 실행 → 사후 상태 확인**을 작은 범위에서 끝까지 연결해야 한다.
