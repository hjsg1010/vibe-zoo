    No separate environment picker

    “URL에 연결할 실행 환경”은
    사용자가 이미 열어둔 그 브라우저다.

    이번 제안에서는 사용자가 환경을 따로 선택하지 않는다. Extension에서 요청한 현재 탭을 기본 작업 대상으로 자동 연결한다.

    내 계정+이 사이트+이 탭+현재 문서

    예: Backend가 “현재 MinIO 탭을 읽어줘” 요청 → Extension이 메뉴·폼을 확인 → 관찰 결과를 Backend로 회신. 실제 웹 조작은 같은 사용자 탭에서 일어난다.

    서버에 새 브라우저를 열어도 사용자 로그인 상태가 자동으로 따라오지는 않는다. 사용자에게 별도의 실행 환경 선택 화면을 요구하지 않는다.

    ‘MCP가 생겼다’의 결과물은 네 부분이다.

    Skill은 Tool을 쓰는 업무 지식 · MCP는 호출 인터페이스

    create_bucket(name)
    02 / ADAPTER

    실행 방법

    사용자 브라우저에서 동작을 수행하는 절차. 시작 화면·입력·상태 변화를 처리.

    관찰 → 입력 → 실행
    03 / VALIDATOR

    성공 확인

    호출 응답만으로 끝내지 않고 실제 업무 결과를 확인. 불확실하면 완료로 보고하지 않음.

    목록에 정확한 이름 존재
    04 / SKILL

    재사용할 업무

    언제 어떤 도구를 쓰고, 어느 조건에서 다음 단계로 넘어가는지 담은 절차.

    기본 Skill / 개인 시연 Skill
    Recommended starting point · not decided

    공통 Gateway + 하나의 Agent 엔진.
    무거운 생성 작업만 선택적으로 분리.

    생성기·Keeper·Skill 생성기는 역할 설정과 도구 구성을 달리해 시작할 수 있다. 오래 걸리는 탐색·평가가 Chat 응답을 막으면 작업 대기열과 Worker를 분리한다. 위 박스마다 프로세스나 컨테이너를 만들 필요는 없다.

    상시: 연결 · 채팅 · 상태 관리작업형: 탐색 · 생성 · 재검증사용자별 k8s 컨테이너 필수 아님

    다음 기술검증으로 정할 항목

    • 1Agent 엔진 / SDK
      브라우저 도구 호출, 긴 작업, 취소를 실제로 지원하는지 확인.
    • 2실행 어댑터 전달 방식
      제한된 워크플로 해석, 패키징, 개발용 설치를 비교. 원격 생성 코드 즉시 실행이나 공개 Chrome Web Store 호환은 미확정.
    • 3동시 작업 수 / 자원
      실제 탐색 시간·메모리·토큰 사용을 측정한 뒤 Worker와 서버 사양 결정.
    • 4지원 범위
      iframe·Canvas·다운로드·다단계 로그인은 사이트별 확인. URL을 받을 수 있는 것과 모든 기능 추출 성공은 구분.

    사용자가 할 수 있는 것

    이 페이지는 시스템 기능과 책임을 검토하기 위한 HTML 시안입니다. 연결된 Agent·MCP 서버·웹앱은 없으며, 전환되는 값은 설명용 예시입니다. MinIO 사전 검증에서 기능 추출·입력 변경 재실행·결과 확인의 가능성을 확인했지만, 범용 자동 생성 플랫폼 구현은 아직 시작하지 않았습니다.
    검증 근거: MinIO 사전 관찰 요약 · Native WebMCP 등록은 선택적 출력이며 이 구조의 전제가 아닙니다.
