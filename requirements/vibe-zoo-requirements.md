# Vibe Zoo 요구사항

- 기준일: 2026-09-08
- 상태: 사용자가 승인한 제품 경험과 MVP 범위의 AI-DLC 입력 기준선
- 개발 대상: Vibe Zoo 브라우저 Extension, 이를 지원하는 Backend, 보조 공유 Store
- 이 문서는 새 AI-DLC 분석의 입력이다. 앞으로 생성할 모든 설계·구현 산출물의 승인 기록을 대신하지 않는다.

## 1. 제품 정의와 핵심 가치

> Vibe Zoo는 사용자가 지금 보고 있는 웹앱을 대화로 사용할 수 있게 만드는 Extension이다. 준비된 도구가 없으면 현재 사이트에서 도구와 기본 Skill을 만들고, 사용자가 보여준 업무를 배워 같은 화면에서 다시 수행한다.

핵심 경험은 **웹앱 방문 → Extension 열기 → 사용할 자산 확인 → 필요하면 생성·검증 → 같은 채팅창에서 업무 수행**이다.

주 사용자는 사내 웹앱으로 업무를 수행하는 사용자다. 서비스 개발팀이 사전에 사이트를 수정하거나 관리자가 사이트를 등록해 놓을 필요가 없어야 한다. 사용자는 별도 CLI나 Agent 앱을 직접 실행하고 브라우저에 연결하는 절차를 거치지 않는다.

사용자간 공유는 가치 있는 보조 기능이다. 개인 업무 수행과 학습이 공유 Store의 가입·게시 절차에 종속되어서는 안 된다.

## 2. 용어

| 용어 | 의미 |
|---|---|
| Keeper | 사용자가 현재 웹앱에서 여는 Extension의 Side Panel 경험 |
| MCP 도구 | 이름·설명·입력 계약을 가지며 실제 실행 경로에 연결된 기능 |
| 실행 어댑터 | 도구 입력을 특정 웹앱에서 수행할 동작으로 연결하는 구현 |
| 기본 Skill | 생성된 도구를 사용하는 방법과 기본 업무 절차 |
| 개인 Skill | 사용자의 시연과 명시적 의도를 재사용 가능한 업무 절차로 만든 자산 |
| Preset | 현재 사이트에 적용할 수 있는 기생성 도구·기본 Skill의 버전 묶음 |
| MCP Generator | 실제 페이지 근거로 도구 계약·어댑터·검증 조건·기본 Skill을 생성하는 Backend 역할 |
| Store | 사용자간 자산 공유·탐색·설치를 위한 별도 웹 UI |

웹페이지에 Native WebMCP가 있다는 전제는 없다. Native WebMCP 등록은 선택적 출력·확장 경로이며 제품이 작동하기 위한 입력 조건이 아니다. 본 제품에서 MCP화는 JSON 정의 생성만을 뜻하지 않는다.

## 3. 기능 요구사항

### FR-01. 현재 웹앱에서 시작

- 사용자가 현재 웹앱에서 Extension을 열면 현재 사이트를 식별하고 호환되는 개인·공유 preset을 확인한다.
- preset이 있으면 사용 가능한 도구와 기본 Skill, 요청 예시를 보여준다.
- 없으면 같은 Panel에서 Backend의 MCP 생성 작업으로 자동 연결한다.
- 사용자가 관리자 화면에 URL을 등록하는 선행 절차는 두지 않는다.
- 임의의 사이트에서도 현재 탭을 기준으로 추출을 요청할 수 있어야 한다. 특정 데모 사이트 목록에 등록되어 있어야만 요청할 수 있는 구조로 만들지 않는다.
- 준비된 자산의 존재와 현재 사용자의 로그인·권한·실행 가능 상태를 구분한다.

### FR-02. 생성 작업의 상태와 제어

- 탐색·생성·검증의 진행 상태, 취소, 실패 이유, 재요청을 같은 Panel에서 제공한다.
- 동일한 사이트·작업을 페이지 이동마다 중복 생성하지 않는다.
- 취소된 작업의 늦은 결과를 자동으로 활성화하지 않는다.
- 전체 사이트의 모든 기능을 탐색하기 전에 검증된 기능부터 사용할 수 있다.
- 후보, 미검증, 실행 가능, 지원 불가, 부분 성공을 구분한다.
- 생성된 개인 자산을 자동으로 Store에 게시하지 않는다.

### FR-03. 실제 페이지를 근거로 MCP와 기본 Skill 생성

- Backend에 MCP Generator 역할이 명시적으로 존재한다.
- 생성기는 요청 사용자의 Extension을 통해 현재 로그인된 탭의 페이지 구조와 수행 가능한 행동을 관찰한다.
- 기능 후보의 이름, 의미, 입력, 실행 절차와 성공 조건을 실제 관찰 근거에 연결한다.
- 결과물은 **도구 계약 + 실행 어댑터 + 성공 판정 + 기본 Skill + 검증 근거 + 버전**이다.
- 메뉴 이름만 보고 검증되지 않은 기능을 사용 가능으로 확정하지 않는다.
- 관찰·시연과 다른 입력으로 동작을 확인해 값만 고정한 녹화 재생과 구분한다.
- 생성된 기본 Skill은 Side Panel의 개인 자산 설정에서도 확인할 수 있다.
- 매뉴얼·추가 시연은 보조 근거로 활용할 수 있으나 매뉴얼 제공이 필수 진입 조건은 아니다.

### FR-04. Keeper Chat/Agent와 실제 실행

- Extension은 채팅·관찰·기록·브라우저 실행을 맡고, 채팅 요청 해석과 생성·학습·Agent 처리는 Backend에 연결한다.
- Backend Agent는 현재 요청에 맞는 Skill과 MCP 도구를 선택해 필요한 여러 단계를 수행할 수 있어야 한다.
- 실제 MCP 도구 검색·호출 경로가 Extension의 브라우저 실행으로 연결되어야 한다.
- 작업은 요청에 연결된 사용자·기기/Extension 연결·탭·문서·페이지 출처에서 수행한다.
- 결과는 같은 채팅창으로 돌아오며 성공·실패·중단·부분 완료를 구분한다.
- 성공 여부는 호출 반환이나 HTTP 상태만으로 확정하지 않고 생성된 항목, 변경된 값 등 관찰 가능한 업무 결과로 검증한다.
- 부작용이 있는 작업은 대상과 변경 내용을 사용자가 이해할 수 있게 보여주고 필요한 확인을 받는다. 탐색이 사용자 모르게 변경 작업을 실행하는 절차가 되어서는 안 된다.
- 연결 단절·로그인 만료·권한 부족 시 다른 사용자나 관리자의 브라우저로 대신 실행하지 않는다.

### FR-05. Record와 의도를 통한 개인 Skill 학습

1. 사용자가 Record를 시작한다.
2. 현재 웹앱에서 업무를 시연한다.
3. Stop 후 수행하려던 의도를 직접 입력한다.
4. Extension은 관찰 가능한 행동 기록과 의도를 Backend로 전달한다.
5. Backend는 절차, 바꿀 입력, 기본값, 성공 조건, 의존 도구가 포함된 Skill 초안을 만든다.
6. 시연과 다른 입력으로 재사용 가능성을 검증한다.
7. 검증한 개인 Skill을 저장하고 같은 채팅에서 사용할 수 있게 한다.

기록 데이터의 종류는 설계에서 정하되, 영상 전체가 반드시 필요한 것으로 가정하지 않는다. 기록 중임을 표시하고 수집 범위를 사용자가 알 수 있게 한다.

기존 도구로 수행 가능한 시연은 이를 조합한 Skill로 만든다. 새 원자 기능이 필요하면 도구 생성 후보로 연결하거나 미지원 단계를 표시하고, 실행 불가능한 문서만 저장한 상태를 준비 완료로 표현하지 않는다.

### FR-06. Side Panel의 개인 설정

- 내 Skill 목록과 현재 사이트에 적용할 수 있는 자산을 제공한다.
- 이름·설명·기본 입력값 편집, 활성/비활성 설정을 지원한다.
- 의존 도구와 호환성, 준비 상태, 사용 중인 버전을 확인할 수 있다.
- 설정과 개인 자산은 새로고침·재접속 이후에도 재사용할 수 있도록 저장한다.
- 공유 Store에 게시하지 않아도 개인 Skill을 만들고 사용할 수 있다.
- 선택한 개인 자산의 공유 진입점은 설정 안에 둘 수 있다.

### FR-07. 사용자간 자산 공유 Store

- 별도 웹 UI에서 도구·Skill 자산을 탐색·공유·설치한다.
- 자산 설명, 작성자, 버전, 적용 대상, 의존 도구와 검증 범위를 표시한다.
- 설치된 자산은 설치 사용자의 로그인된 실행 환경에 연결하고 호환성을 확인한다.
- 자산 공유와 개인 계정·세션·대화·원본 업무 데이터의 공유를 구분한다.
- Store는 개인 사용 흐름보다 후순위다. MVP에서 간결하게 구현하되 개인 설정을 Store로 대체하지 않는다.

### FR-08. 검증을 거치는 자기개선

- 실행 실패, 사용자 수정, 추가 시연을 도구·Skill 개선 근거로 사용할 수 있다.
- 실패 원인과 변경 이유를 설명하는 새 버전 후보를 만든다.
- 해당 실패 사례와 관련된 기존 성공 사례를 재검증한다.
- 후보와 현재 사용 버전을 구분하며 검증되지 않은 변경을 조용히 적용하지 않는다.
- 변경이 실패하면 정상 버전을 유지하거나 이전 버전으로 되돌릴 수 있어야 한다.
- 학습은 업무 지식·어댑터·Skill의 개선을 뜻한다. 모델 파인튜닝이나 완전 자율 운영을 필수로 요구하지 않는다.

### FR-09. 연결과 대화의 일관성

- 대화, 장기 생성 작업, 설치 자산, 실제 브라우저 연결을 구분해 관리한다.
- 같은 사용자의 재접속과 탭 변경 시 대화·자산을 이어갈 수 있는 상태 모델을 설계한다.
- 현재 실행 대상 사이트와 탭을 사용자에게 명확히 보여준다.
- 다른 사이트로 작업을 넘기는 경우 각 대상 탭의 연결·권한을 별도로 확인해야 한다.
- 모든 사이트간 자동 업무 연쇄 실행은 초기 필수 시연 범위가 아니다. 다른 사용자의 대화나 세션을 섞는 방식으로 연속성을 구현해서는 안 된다.

## 4. MVP 범위와 우선순위

| 우선순위 | 결과 |
|---|---|
| 핵심 완주 | preset 없는 현재 웹앱에서 생성 → 실제 MCP 호출 → 사용자 탭 실행 → 결과 확인 |
| 핵심 개인화 | Record + 의도 → Skill 생성 → 다른 입력으로 검증 → 내 Skill 편집·재사용 |
| 확장 시연 | Store 공유·설치, 실패를 이용한 개선 후보와 버전 검증 |
| 후속 확장 | 네이티브 PC 앱, 전 사이트 자율 탐색, 광범위한 여러 앱 업무 연결, 대규모 조직 운영 |

첫 실제 전체 흐름 검증 대상은 MinIO Console로 한다. MinIO 전용 구현을 미리 숨겨 두고 범용 생성으로 표시해서는 안 된다. 다른 사이트에서도 같은 추출 요청 경로에 진입할 수 있어야 한다.

**임의의 사이트에서 요청할 수 있다는 것과, 모든 사이트의 모든 기능을 성공적으로 자동 생성한다는 것은 다른 약속이다.** 실제 지원 범위는 관찰·실행 검증을 근거로 표시한다.

## 5. 수용조건

| ID | 완료 증거 |
|---|---|
| AC-01 | preset 없는 현재 웹앱에서 Extension을 열면 별도 관리자 등록 없이 생성 흐름이 시작된다. |
| AC-02 | 생성된 도구 계약·실행 어댑터·성공 조건·기본 Skill이 실제 페이지 관찰 근거 및 버전에 연결된다. |
| AC-03 | 실제 MCP 도구 검색·호출을 통해 해당 사용자의 브라우저에서 기능을 실행하고 화면/상태 결과를 확인한다. |
| AC-04 | 관찰 또는 시연 때와 다른 입력으로 재실행하여 고정값 재생이 아님을 확인한다. |
| AC-05 | Record와 명시적 의도로 개인 Skill을 만들고 기본값을 바꿔 재사용한다. |
| AC-06 | 내 Skill의 편집·활성 상태가 저장되고 후속 채팅 실행에 반영된다. |
| AC-07 | 공유한 자산의 특정 버전을 다른 사용자가 설치해 자신의 세션에서 검증한다. |
| AC-08 | 재현 가능한 실패로 개선 후보를 만들고, 실패 해결과 관련 기존 기능 유지 여부를 검증하며 이전 버전을 보존한다. |
| AC-09 | 취소·부분 성공·로그인 만료·연결 단절·지원 불가를 성공으로 표시하지 않고 잘못된 탭에서 실행하지 않는다. |
| AC-10 | 사전 등록하지 않은 다른 사이트도 같은 추출 요청 경로로 진입하며, 관찰 가능한 범위와 실패 이유가 표시된다. |

정량 지연·자원 목표, 초기 관찰 지원 행렬, 사용 기술은 [constraints.md](constraints.md)의 미정 항목을 설계·기술검증에서 구체화한다. 부차 기능의 규모를 조정해야 하면 핵심 경험을 보존하며 변경 근거와 사용자 결정을 기록한다.

## 6. 기능 시안과 Zoo 콘셉트

[사용자 경험 HTML](../prototypes/vibe-zoo-experience/index.html)과 [시스템 구조 HTML](../prototypes/vibe-zoo-experience/architecture.html)은 승인된 검토 참고 자료다. 세부 디자인을 그대로 구현해야 한다는 뜻은 아니며 실제 연동 완료의 증거도 아니다.

| 제품 요소 | Zoo 표현 |
|---|---|
| 사용자 | 직접 가르치고 선택하는 사육사 |
| Extension | Keeper, 현장 도우미 |
| 웹앱 | Habitat, 서식지 |
| 웹앱별 도구·기본 Skill 묶음 | 각자 기능을 가진 동물 |
| MCP 도구 | 동물이 할 수 있는 기능 |
| 개인 Skill | 가르친 행동·습관 |
